1. Concepto, funciones y evolución

Un sistema operativo (SO) es el software de base que gestiona los recursos del hardware y ofrece servicios a los programas y al usuario. Actúa como intermediario entre aplicaciones y hardware.

Dos visiones clásicas:

  • Máquina extendida (virtual): oculta la complejidad del hardware y ofrece una interfaz más cómoda (abstracciones: proceso, fichero, socket).

  • Gestor de recursos: reparte CPU, memoria, E/S y almacenamiento entre procesos de forma eficiente, justa y segura.

1.1. Funciones (elementos constitutivos)

Características deseables: eficiencia, fiabilidad, seguridad, escalabilidad, portabilidad, facilidad de uso y capacidad de evolución.

1.2. Evolución histórica

  1. Sin SO (años 40): programación directa en máquina, tarjetas y paneles.

  2. Procesamiento por lotes (batch, años 50): trabajos agrupados; monitor residente; JCL (lenguaje de control de trabajos).

  3. Multiprogramación (años 60): varios programas en memoria; la CPU cambia de uno a otro cuando uno espera E/S. Aparece spooling.

  4. Tiempo compartido (time-sharing): reparto de CPU en cuantos; usuarios interactivos con terminales (CTSS, MULTICS, después UNIX, 1969, Bell Labs).

  5. Ordenadores personales (años 80): MS-DOS, Mac OS, Windows; GUI.

  6. SO en red y distribuidos: recursos compartidos en red; un sistema distribuido se presenta al usuario como un único sistema.

  7. Móviles, virtualización y nube: Android, iOS; hipervisores; contenedores.

  • Multitarea cooperativa: el proceso cede voluntariamente la CPU (Windows 3.x, Mac OS clásico).

  • Multitarea apropiativa (preemptive): el SO retira la CPU (Windows NT y sucesores, Unix, Linux).

  • Multiprogramación = varios programas en memoria; multiproceso = varias CPU.

2. Estructura del sistema operativo

El núcleo (kernel) es la parte del SO que se ejecuta en modo privilegiado y permanece residente en memoria.

2.1. Modos de ejecución

  • Modo núcleo (kernel, supervisor, privilegiado): acceso total al hardware e instrucciones privilegiadas.

  • Modo usuario: acceso restringido; las aplicaciones piden servicios al núcleo.

  • En x86 se implementa con anillos de protección: ring 0 = núcleo, ring 3 = usuario.

2.2. Llamadas al sistema, interrupciones y excepciones

  • Llamada al sistema (system call): interfaz programática para pedir un servicio al núcleo; provoca el paso de modo usuario a modo núcleo (trap). Ejemplos POSIX: fork(), exec(), wait(), exit(), open(), read(), write(), close(), kill().

  • En Windows las aplicaciones usan la API Win32/WinAPI, que llama a la API nativa (ntdll.dll).

  • Interrupción hardware: señal asíncrona de un dispositivo (fin de E/S, reloj). La CPU salva el contexto y ejecuta la rutina de servicio (ISR) a través del vector de interrupciones.

  • Excepción / trap: evento síncrono causado por la instrucción en curso (división por cero, fallo de página, llamada al sistema).

  • Reloj (timer): genera interrupciones periódicas que permiten la multitarea apropiativa.

  • Debate clásico Tanenbaum–Torvalds (1992): micronúcleo frente a monolítico.

2.4. Arranque (boot)

  1. Firmware (BIOS o UEFI) ejecuta el POST (Power-On Self Test).

  2. Localiza el cargador: BIOS lee el MBR (512 bytes, tabla MBR, máx. 4 particiones primarias, discos hasta 2 TiB); UEFI lee la partición ESP de un disco GPT (128 particiones por defecto en Windows).

  3. Cargador de arranque: GRUB 2 (Linux), Windows Boot Manager (bootmgr).

  4. Carga del núcleo e inicio del primer proceso: init / systemd (PID 1) en Linux; smss.exe en Windows.

  5. Secure Boot (UEFI) verifica firmas digitales de los cargadores.

2.5. Virtualización

  • Hipervisor tipo 1 (nativo, bare-metal): sobre el hardware. Ej.: VMware ESXi, Microsoft Hyper-V, Xen, KVM.

  • Hipervisor tipo 2 (alojado, hosted): sobre un SO anfitrión. Ej.: VirtualBox, VMware Workstation.

  • Contenedores: virtualización a nivel de SO; comparten el núcleo del anfitrión. En Linux se basan en namespaces (aislamiento) y cgroups (limitación de recursos). Ej.: Docker, Podman; orquestación con Kubernetes.

3. Procesos, hilos y planificación

Un proceso es un programa en ejecución: código + datos + pila + estado de la CPU + recursos asignados. El programa es pasivo; el proceso es activo.

3.1. Bloque de control de proceso (BCP / PCB)

Estructura del núcleo con la información de cada proceso: PID, estado, contador de programa, registros, prioridad, información de memoria (tablas de páginas), ficheros abiertos, contabilidad. El cambio de contexto guarda el PCB del proceso saliente y carga el del entrante; es sobrecarga pura (no hace trabajo útil).

3.2. Estados de un proceso (modelo de 5 estados)

EstadoSignificado
NuevoSe está creando
Listo (preparado)Espera CPU
En ejecuciónUsa la CPU
Bloqueado (en espera)Espera un evento (E/S, señal)
TerminadoHa finalizado

Transiciones: Listo → Ejecución (activación / dispatch); Ejecución → Listo (fin de cuanto o expropiación); Ejecución → Bloqueado (espera E/S); Bloqueado → Listo (ocurre el evento). No existe la transición Bloqueado → Ejecución directa. Con suspensión (swap a disco) aparecen los estados listo-suspendido y bloqueado-suspendido (modelo de 7 estados).

  • Zombi (Unix): proceso terminado cuyo padre aún no ha recogido su estado con wait().

  • Huérfano: su padre murió; lo adopta init/systemd (PID 1).

  • En Unix, fork() crea un hijo copia del padre (devuelve 0 al hijo y el PID del hijo al padre); exec() sustituye la imagen del proceso.

3.3. Hilos (threads)

Un hilo es la unidad básica de uso de CPU. Los hilos de un proceso comparten código, datos, ficheros abiertos y espacio de direcciones; cada hilo tiene su propia pila, registros y contador de programa.

  • Ventajas: creación y cambio de contexto más baratos que entre procesos; paralelismo en multinúcleo.

  • Hilos de usuario (ULT): gestionados por una biblioteca; el núcleo no los ve; si uno se bloquea, se bloquea todo el proceso.

  • Hilos de núcleo (KLT): gestionados por el SO (Windows, Linux).

  • Modelos: muchos a uno, uno a uno (Linux, Windows), muchos a muchos.

  • API estándar en Unix: POSIX Threads (pthreads).

3.4. Planificación de la CPU

Niveles: largo plazo (admite trabajos, controla el grado de multiprogramación), medio plazo (suspende/reanuda, swapping), corto plazo (elige el siguiente proceso listo; el dispatcher hace el cambio).

Criterios: utilización de CPU y rendimiento (throughput) a maximizar; tiempo de retorno (turnaround), tiempo de espera y tiempo de respuesta a minimizar.

  • Tiempo de retorno = fin − llegada. Tiempo de espera = retorno − ráfaga de CPU.

3.5. Comunicación entre procesos (IPC)

  • Memoria compartida (rápida, requiere sincronización).

  • Paso de mensajes: send/receive, síncrono o asíncrono.

  • Tuberías (pipes): sin nombre (|, entre procesos emparentados) y con nombre (FIFO, mkfifo).

  • Señales (Unix): SIGKILL (9, no se puede capturar), SIGTERM (15, terminación por defecto de kill), SIGINT (2, Ctrl+C), SIGSTOP (no capturable), SIGHUP (1).

  • Sockets: comunicación local o por red.

4. Concurrencia, sincronización e interbloqueo

Cuando varios procesos o hilos acceden a datos compartidos, el resultado puede depender del orden de ejecución: condición de carrera (race condition).

4.1. Sección crítica

Fragmento de código que accede a recursos compartidos. Una solución correcta cumple tres requisitos:

  1. Exclusión mutua: solo un proceso a la vez en la sección crítica.

  2. Progreso: si nadie está dentro, la decisión de quién entra no se pospone indefinidamente.

  3. Espera limitada (acotada): límite al número de veces que otros entran antes que uno que lo pidió.

4.2. Mecanismos

MecanismoDescripción
Algoritmos softwareDekker (2 procesos, primera solución correcta), Peterson (2 procesos), panadería de Lamport (n procesos)
Instrucciones hardwareTest-and-Set, Compare-and-Swap, deshabilitar interrupciones (solo monoprocesador)
Cerrojo de giro (spinlock)Espera activa; útil en multiprocesador con esperas muy cortas
MutexCerrojo binario con propietario: lock/unlock
Semáforo (Dijkstra, 1965)Entero con operaciones atómicas P / wait / down (decrementa; bloquea si < 0) y V / signal / up (incrementa; despierta). Binario (0/1) o contador

Problemas clásicos: productor-consumidor (búfer limitado), lectores-escritores, cena de los filósofos (Dijkstra), barbero dormilón.

4.3. Interbloqueo (deadlock)

Conjunto de procesos bloqueados de forma permanente, cada uno esperando un recurso que tiene otro del conjunto.

Condiciones de Coffman (1971) — necesarias y, juntas, suficientes (con recursos de una sola instancia):

  1. Exclusión mutua: el recurso no se puede compartir.

  2. Retención y espera (hold and wait): se retiene un recurso mientras se espera otro.

  3. No expropiación (no apropiación): el recurso solo lo libera voluntariamente quien lo tiene.

  4. Espera circular: cadena circular P1 → P2 → … → Pn → P1.

Se modela con un grafo de asignación de recursos: un ciclo implica interbloqueo si cada recurso tiene una sola instancia; con varias instancias, el ciclo es condición necesaria pero no suficiente.

EstrategiaCómo
PrevenciónRomper una de las 4 condiciones (p. ej., pedir todos los recursos a la vez; ordenar recursos para evitar la espera circular)
EvitaciónSolo conceder si el sistema queda en estado seguro: algoritmo del banquero (Dijkstra)
Detección y recuperaciónDetectar ciclos y recuperar: matar procesos, expropiar recursos, rollback
Ignorar (algoritmo del avestruz)Lo que hacen en la práctica Unix/Linux y Windows para la mayoría de recursos

  • Estado seguro: existe al menos una secuencia en la que todos los procesos pueden terminar. Un estado inseguro no implica necesariamente interbloqueo.

  • Inanición (starvation): un proceso espera indefinidamente aunque el sistema avance. Livelock: los procesos cambian de estado sin progresar.

  • Inversión de prioridades: un proceso de baja prioridad retiene un recurso que necesita uno de alta; solución: herencia de prioridad.

5. Gestión de memoria

El gestor de memoria asigna memoria a los procesos, la protege y la recupera. Traduce direcciones lógicas (virtuales) a direcciones físicas mediante la MMU (Memory Management Unit, hardware).

5.1. Jerarquía y conceptos

  • Jerarquía (de más rápida a más lenta): registros → caché L1/L2/L3 → RAM → SSD/disco.

  • Principio de localidad: temporal (lo usado se reutiliza pronto) y espacial (se usa lo cercano). Justifica cachés y memoria virtual.

  • Reubicación: estática (en carga) o dinámica (en ejecución, con registro base).

  • Protección: registros base y límite; bits de protección en páginas.

  • Intercambio (swapping): mover procesos completos entre RAM y disco.

5.2. Técnicas de asignación

TécnicaIdeaFragmentación
Particiones fijasMemoria dividida en particiones de tamaño fijoInterna
Particiones variablesCada proceso recibe lo que necesitaExterna → solución: compactación
PaginaciónMemoria lógica en páginas y física en marcos del mismo tamañoSolo interna (en la última página); no hay externa
SegmentaciónDivisión lógica en segmentos de tamaño variable (código, datos, pila)Externa
Segmentación paginadaSegmentos divididos en páginasInterna

Algoritmos de ubicación (particiones variables): primer ajuste (first fit, el primer hueco suficiente; rápido), mejor ajuste (best fit, el hueco más pequeño suficiente; deja huecos minúsculos), peor ajuste (worst fit, el mayor), siguiente ajuste (next fit). Linux usa el sistema buddy (bloques potencia de 2).

5.3. Paginación

  • Dirección lógica = número de página + desplazamiento (offset). Con páginas de 4 KiB (2^12), los 12 bits bajos son el desplazamiento.

  • Tabla de páginas (una por proceso): página → marco, con bits de presencia/validez, modificado (dirty), referenciado (accedido) y protección.

  • TLB (Translation Lookaside Buffer): caché asociativa de traducciones; evita acceder a la tabla en cada referencia.

  • Tablas multinivel (x86-64 usa 4 niveles; 5 con LA57), tablas invertidas (una entrada por marco físico) y páginas grandes (huge pages, 2 MiB/1 GiB).

5.4. Memoria virtual

Permite ejecutar procesos mayores que la memoria física: solo están en RAM las páginas en uso; el resto, en disco (swap en Linux, pagefile.sys en Windows).

  • Paginación por demanda: una página se carga solo cuando se referencia.

  • Fallo de página (page fault): excepción al acceder a una página no presente; el SO la trae de disco y reintenta la instrucción.

  • Hiperpaginación (thrashing): el sistema pasa más tiempo paginando que ejecutando; se combate con el modelo del conjunto de trabajo (working set) o reduciendo la multiprogramación.

  • Copia en escritura (copy-on-write): tras fork(), padre e hijo comparten páginas hasta que uno escribe.

5.5. Algoritmos de reemplazo de páginas

AlgoritmoCriterioNota

Anomalía de Belady: con FIFO, más marcos pueden producir más fallos. Ejemplo: cadena 1,2,3,4,1,2,5,1,2,3,4,5 → 9 fallos con 3 marcos y 10 con 4. LRU y Óptimo (algoritmos de pila) no la sufren.

6. Entrada/salida y sistemas de ficheros

6.1. Gestión de E/S

  • Controlador de dispositivo (driver): software del núcleo que habla con el hardware concreto; ofrece una interfaz uniforme.

  • Técnicas de E/S: programada (sondeo, polling), la CPU pregunta continuamente; por interrupciones, el dispositivo avisa; DMA (Direct Memory Access), el controlador DMA transfiere bloques a memoria sin la CPU y solo interrumpe al final.

  • Buffering (memoria intermedia), caching y spooling (cola en disco para dispositivos no compartibles, p. ej. impresoras).

  • Dispositivos de bloque (discos; acceso aleatorio) y de carácter (teclado, terminal; flujo de bytes). En Unix aparecen en /dev como b y c.

Planificación de disco (HDD): FCFS; SSTF (menor tiempo de búsqueda primero; inanición); SCAN (ascensor: recorre de un extremo a otro); C-SCAN (circular, vuelve al inicio sin atender); LOOK / C-LOOK (como SCAN/C-SCAN pero solo hasta la última petición). En SSD/NVMe se usan planificadores sencillos (en Linux, none o mq-deadline).

6.2. Conceptos de sistema de ficheros

  • Fichero: conjunto de datos con nombre y atributos (tamaño, fechas, propietario, permisos).

  • Directorio: estructura que asocia nombres con ficheros; jerárquica en árbol (Unix: raíz única /; Windows: una raíz por unidad C:\).

  • Rutas absolutas (desde la raíz) y relativas (desde el directorio actual).

  • Journaling (registro por diario): antes de modificar metadatos se anotan en un diario; tras un corte se reproduce el diario y se evita un fsck/chkdsk completo.

Métodos de asignación de bloques:

MétodoIdeaEjemplo
ContiguaBloques consecutivosCD-ROM (ISO 9660)
EnlazadaCada bloque apunta al siguiente; variante con tablaFAT (File Allocation Table)
IndexadaBloque índice con punterosi-nodos en Unix (punteros directos, indirecto simple, doble y triple)
Por extensiones (extents)Rangos contiguos de bloquesext4, NTFS, XFS

i-nodo (Unix): guarda todos los metadatos del fichero excepto su nombre (el nombre está en el directorio): tipo, permisos, propietario, tamaño, marcas de tiempo, contador de enlaces y punteros a bloques.

  • Enlace duro (hard link): otra entrada de directorio al mismo i-nodo; no cruza sistemas de ficheros ni (en general) apunta a directorios. ln origen destino.

  • Enlace simbólico (soft link): fichero que contiene una ruta; puede cruzar sistemas de ficheros; queda roto si se borra el original. ln -s origen destino.

7.3. Registro de Windows

Base de datos jerárquica de configuración. Se edita con regedit. Claves raíz (hives):

  • HKEY_LOCAL_MACHINE (HKLM): configuración del equipo (hardware, software, SAM, SECURITY, SYSTEM).

  • HKEY_CURRENT_USER (HKCU): perfil del usuario con sesión iniciada (NTUSER.DAT).

  • HKEY_USERS (HKU): todos los perfiles cargados.

  • HKEY_CLASSES_ROOT (HKCR): asociaciones de ficheros y objetos COM.

  • HKEY_CURRENT_CONFIG (HKCC): perfil de hardware actual.

7.4. Seguridad y dominio

  • Cuentas locales en la SAM; identificadores SID; permisos NTFS mediante ACL compuestas de ACE.

  • UAC (Control de cuentas de usuario, desde Vista): ejecuta incluso a los administradores con token restringido.

  • BitLocker: cifrado de volumen completo (usa TPM). EFS: cifrado por fichero en NTFS.

  • Microsoft Defender (antivirus integrado) y Firewall de Windows Defender.

  • Active Directory Domain Services (AD DS): servicio de directorio; controladores de dominio; estructura bosque → árbol → dominio → unidades organizativas (OU); protocolos LDAP, Kerberos (autenticación por defecto) y DNS (imprescindible). GPO (directivas de grupo) aplicadas en orden LSDOU: Local, Sitio, Dominio, OU.

  • Roles de servidor habituales: AD DS, DNS, DHCP, IIS (servidor web), servicios de archivos, Hyper-V, Escritorio remoto (RDS, protocolo RDP, puerto 3389), WSUS.

8. Sistemas Unix y Linux

8.1. Historia y estándares

  • UNIX: creado en 1969 en los Bell Labs (AT&T) por Ken Thompson y Dennis Ritchie; reescrito en C (1973), lo que lo hizo portable.

  • Ramas: System V (AT&T) y BSD (Universidad de Berkeley). Derivados: Solaris (Sun/Oracle), AIX (IBM), HP-UX, FreeBSD, OpenBSD, NetBSD, macOS (Darwin/XNU, certificado UNIX).

  • POSIX (IEEE 1003): estándar de interfaz de los sistemas tipo Unix. Single UNIX Specification: la marca UNIX la gestiona The Open Group.

  • GNU (Richard Stallman, 1983, Free Software Foundation): herramientas libres; licencia GPL.

  • Linux: núcleo creado por Linus Torvalds en 1991, licencia GPLv2. Un sistema completo es GNU/Linux = núcleo + herramientas GNU + otros componentes, empaquetados en distribuciones.

  • La rama de núcleo Linux 7.0 se publicó en abril de 2026; el núcleo ya admite código en Rust además de C.

Filosofía Unix: «todo es un fichero»; programas pequeños que hacen una cosa bien y se combinan con tuberías; texto plano como interfaz.

8.4. Permisos

Cada fichero tiene permisos para propietario (u), grupo (g) y otros (o): r = 4, w = 2, x = 1.

NotaciónOctalSignificado
rwxr-xr-x755Todo para el propietario; leer y ejecutar el resto
rw-r--r--644Fichero típico
rw-------600Solo el propietario lee y escribe
rwxrwxrwx777Todo para todos

  • En un directorio: r = listar, w = crear/borrar entradas, x = atravesar (entrar).

  • Permisos especiales: SUID (4000, s en el propietario: se ejecuta con el UID del dueño, p. ej. /usr/bin/passwd), SGID (2000, s en el grupo) y sticky bit (1000, t: en /tmp solo el propietario borra sus ficheros).

  • umask: máscara que se resta a los permisos por defecto (666 ficheros, 777 directorios). Con umask 022 → ficheros 644 y directorios 755.

  • Comandos: chmod 750 f, chmod u+x f, chown usuario:grupo f, chgrp. ACL extendidas: getfacl, setfacl. Control de acceso obligatorio: SELinux (Red Hat) y AppArmor (Ubuntu, SUSE).

8.6. Arranque y servicios

  • systemd es el sistema de inicio de la mayoría de distribuciones (sustituyó a SysV init). Gestiona unidades (.service, .target, .timer, .mount).

  • systemctl start|stop|restart|status|enable|disable servicio; registros con journalctl.

  • Los targets sustituyen a los niveles de ejecución (runlevels) de SysV: 0 = apagar, 1 = monousuario, 3 = multiusuario en texto (multi-user.target), 5 = gráfico (graphical.target), 6 = reiniciar.

9. Sistemas operativos para dispositivos móviles

Los SO móviles priorizan bajo consumo energético, interfaz táctil, conectividad (móvil, Wi-Fi, Bluetooth, NFC), sensores y un modelo de seguridad basado en aislamiento de aplicaciones (sandbox) y permisos concedidos por el usuario. Hoy el mercado es un duopolio Android / iOS.

9.1. Android

  • Desarrollado por Google (empresa Android Inc. adquirida en 2005; primer móvil en 2008). Proyecto abierto AOSP (Android Open Source Project), licencia principal Apache 2.0; el núcleo Linux es GPLv2.

  • Basado en un núcleo Linux modificado.

  • Versión actual: Android 17 (API nivel 37), estable para Pixel desde el 16 de junio de 2026; el resto de fabricantes la despliega a lo largo del año (notas de versión, Tom's Guide). Google publica ahora la versión mayor en el segundo trimestre.

Arquitectura (de abajo arriba):

CapaContenido
Núcleo LinuxDrivers, gestión de memoria y procesos, energía, Binder (IPC)
HALInterfaces estándar para cámara, audio, sensores…
Bibliotecas nativas C/C++ + ARTSQLite, OpenGL ES/Vulkan, WebKit, libc (Bionic). ART (Android Runtime) sustituyó a la máquina virtual Dalvik en Android 5.0; usa compilación AOT + JIT; ejecuta bytecode DEX
Framework de API Java/KotlinActivity Manager, Package Manager, Notification Manager, Content Providers, View System

Componentes de una app: Activity (pantalla), Service (tarea en segundo plano), Broadcast Receiver (responde a eventos del sistema), Content Provider (comparte datos). Se comunican con Intents. Se declaran en AndroidManifest.xml (permisos incluidos).

  • Cada app se ejecuta con su propio UID de Linux y en su propio proceso (sandbox). SELinux en modo enforcing.

  • Permisos en tiempo de ejecución desde Android 6.0.

  • Lenguajes: Kotlin (preferido por Google desde 2019) y Java; IDE Android Studio.

  • Formatos: APK (paquete instalable) y AAB (Android App Bundle, obligatorio para apps nuevas en Google Play desde agosto de 2021).

  • Actualización modular de componentes del sistema mediante Project Mainline (Google Play System Updates).

9.2. iOS / iPadOS

  • De Apple, desde 2007 (primer iPhone). Propietario y cerrado; solo en hardware Apple.

  • Base Darwin (común con macOS) y núcleo híbrido XNU (Mach + BSD). Sistema de ficheros APFS.

  • Versión actual: iOS 27, publicada el 14 de septiembre de 2026; compatible desde el iPhone 11 y el iPhone SE (2.ª generación) (MacRumors). Desde 2025 Apple numera sus sistemas por el año siguiente (iOS 26 → iOS 27).

  • Capas: Core OS (núcleo, seguridad, energía) → Core Services (Foundation, SQLite, Core Data, iCloud) → Media (Core Graphics, Core Audio, Metal) → Cocoa Touch (UIKit; interfaz, eventos táctiles). Interfaz moderna con SwiftUI.

  • Lenguajes: Swift (2014) y Objective-C; IDE Xcode (solo macOS). Paquetes .ipa.

  • Seguridad: sandbox por app, firma de código obligatoria, revisión en App Store, Secure Enclave (claves, Face ID/Touch ID), cifrado de datos por defecto.

  • En la UE, la Ley de Mercados Digitales (DMA) ha obligado a Apple a permitir tiendas alternativas en iOS.

9.4. Otros sistemas y gestión corporativa

  • HarmonyOS (Huawei), KaiOS (móviles básicos), Wear OS y watchOS (relojes). Históricos: Symbian (Nokia), BlackBerry OS, Windows Phone / Windows 10 Mobile (sin soporte), Firefox OS.

Esquema de repaso

  • SO = máquina extendida + gestor de recursos. Subsistemas: procesos, memoria, E/S, ficheros, seguridad, red, interfaz.

  • Modo núcleo (ring 0) frente a modo usuario (ring 3); se pasa con llamadas al sistema, interrupciones y excepciones.

  • Núcleos: monolítico (Linux, modular), micronúcleo (Mach, MINIX 3, QNX), híbrido (Windows NT, XNU).

  • Arranque: BIOS + MBR (4 primarias, 2 TiB) o UEFI + GPT (ESP, Secure Boot); PID 1 = systemd.

  • Hipervisor tipo 1 (ESXi, Hyper-V, KVM) / tipo 2 (VirtualBox); contenedores = namespaces + cgroups.

  • Proceso = programa en ejecución; PCB; 5 estados; no existe bloqueado → ejecución. Los hilos comparten código, datos y ficheros; cada uno tiene pila, registros y PC propios.

  • FCFS (convoy), SJF (óptimo en espera media; inanición), SRTF, prioridades + envejecimiento, RR (cuanto grande = FCFS).

  • Sección crítica: exclusión mutua, progreso, espera limitada. Semáforos P/wait y V/signal; monitores.

  • Coffman: exclusión mutua, retención y espera, no expropiación, espera circular. Banquero = evitación; avestruz = ignorar.

  • Paginación: sin fragmentación externa; sí interna. Segmentación: externa. TLB = caché de traducciones.

  • Memoria virtual: paginación por demanda, fallo de página, thrashing, conjunto de trabajo, copy-on-write.

  • Reemplazo: OPT (irrealizable), FIFO (anomalía de Belady), LRU, reloj.

  • E/S: sondeo, interrupciones, DMA; disco: SSTF, SCAN (ascensor), C-SCAN, LOOK.

  • i-nodo = metadatos sin el nombre; enlace duro (mismo i-nodo) frente a simbólico (ruta).

  • FAT32 (fichero máx. 4 GiB − 1 B), exFAT, NTFS (MFT, ACL, EFS, journaling), ReFS, ext4 (extents), XFS (RHEL), Btrfs (CoW), APFS.

  • Windows: Windows 10 sin soporte desde el 14/10/2025; Windows 11 26H2 (sep. 2026); Windows Server 2025 LTSC. Arquitectura: HAL, núcleo, Ejecutivo, lsass, csrss. Registro: HKLM, HKCU, HKU, HKCR, HKCC.

  • AD DS: bosque/árbol/dominio/OU, Kerberos, LDAP, GPO en orden LSDOU. PowerShell = objetos, Verbo-Sustantivo.

  • Unix (1969, Thompson y Ritchie), POSIX, GNU (1983), Linux (Torvalds, 1991, GPLv2); Ubuntu 26.04 LTS, Debian 13, RHEL 10.

  • Permisos r=4 w=2 x=1; 755/644/600; SUID 4000, SGID 2000, sticky 1000; umask 022 → 644/755; /etc/shadow; root UID 0.

  • Móviles: Android 17 (API 37) sobre Linux, ART, Activity/Service/Broadcast Receiver/Content Provider, APK/AAB; iOS 27 sobre XNU, Swift, sandbox, App Store.
