1. Lenguajes de interrogación de bases de datos y el estándar SQL

Un lenguaje de interrogación (query language) permite consultar y manipular los datos de una BD. Clasificación:

TipoCaracterísticaEjemplos
FormalesBase matemáticaÁlgebra relacional (procedimental), cálculo relacional de tuplas y de dominios (declarativos)
Comerciales relacionalesBasados en los formalesSQL (cálculo de tuplas + álgebra), QUEL (Ingres), QBE (Query By Example, IBM, cálculo de dominios; modelo de las consultas gráficas de Access)
Lógicos / deductivosReglasDatalog
Otros modelosNo relacionalesXQuery/XPath (XML), SPARQL (RDF, W3C), Cypher (Neo4j), GQL (grafos, ISO/IEC 39075:2024, publicada el 12-04-2024), MQL (MongoDB)

SQL es declarativo (se dice qué se quiere, no cómo obtenerlo: eso lo decide el optimizador), relacionalmente completo y no es un lenguaje de programación completo en su núcleo (las extensiones procedimentales lo son).

Modos de uso de SQL: interactivo (consola), embebido en un lenguaje anfitrión (Embedded SQL, con precompilador: Pro*C, SQLJ), dinámico (sentencias construidas en tiempo de ejecución) y mediante API de llamadas (SQL/CLI, ODBC, JDBC).

1.1. Historia y versiones del estándar

  • SEQUEL (Structured English Query Language): D. Chamberlin y R. Boyce, IBM, a mediados de los 70, para el prototipo System R. Por motivos de marca pasó a llamarse SQL.

  • 1979: Relational Software (hoy Oracle) lanza el primer SGBD comercial con SQL.

  • 1986: primer estándar ANSI X3.135-1986; ISO lo adopta en 1987 (ISO 9075). Hoy la norma es ISO/IEC 9075, que INCITS adopta en EE. UU. (de ahí el nombre popular «ANSI SQL»).

VersiónNovedades principales (dato de test)
SQL-86 / SQL-89Primer estándar; SQL-89 añade integridad referencial
SQL-92 (SQL2)Gran revisión: JOIN explícitos, niveles de aislamiento, tipos fecha/hora, CASE, niveles de conformidad (entry, intermediate, full). En 1996 se añade SQL/PSM (procedimientos almacenados)
SQL:1999 (SQL3)Disparadores (triggers), consultas recursivas (WITH RECURSIVE), tipos definidos por el usuario y características objeto-relacionales, BOOLEAN
SQL:2003Funciones de ventana (OVER), MERGE, secuencias, columnas identidad, SQL/XML
SQL:2006Amplía SQL/XML (XQuery)
SQL:2008TRUNCATE, disparadores INSTEAD OF, FETCH FIRST n ROWS
SQL:2011Datos temporales (tablas versionadas por periodo)
SQL:2016JSON (funciones SQL/JSON), reconocimiento de patrones en filas (MATCH_RECOGNIZE), funciones de tabla polimórficas
SQL:2019Parte 15: arrays multidimensionales (SQL/MDA)
SQL:2023Vigente. Nueva parte 16 SQL/PGQ (consultas sobre grafos de propiedades), tipo de dato JSON con notación de punto simplificada, funciones GREATEST, LEAST, LPAD, RPAD, LTRIM, RTRIM, ANY_VALUE

A fecha de este tema la edición vigente es ISO/IEC 9075:2023 (SQL:2023), en 11 partes (1 Framework, 2 Foundation, 3 CLI, 4 PSM, 9 MED, 10 OLB, 11 Schemata, 13 JRT, 14 XML, 15 MDA, 16 PGQ). La siguiente edición está en elaboración (borrador de comité ISO/IEC CD 9075-1, edición 7). Fuentes: Oracle, publicación de SQL:2023, ISO, CD 9075-1, ANSI, historia de SQL, IEC, GQL.

Ningún SGBD comercial implementa el estándar completo; cada uno tiene su dialecto (PL/SQL de Oracle, T-SQL de SQL Server, PL/pgSQL de PostgreSQL).

2. Sublenguajes de SQL y tipos de datos

SublenguajeFinalidadSentencias
DDL (Data Definition Language)Definir estructuras (esquema)CREATE, ALTER, DROP, TRUNCATE, RENAME, COMMENT*
DML (Data Manipulation Language)Consultar y modificar datosSELECT, INSERT, UPDATE, DELETE, MERGE
DCL (Data Control Language)PermisosGRANT, REVOKE
TCL (Transaction Control Language)TransaccionesCOMMIT, ROLLBACK, SAVEPOINT, SET TRANSACTION, START TRANSACTION

* Según el producto. Algunos autores separan SELECT como DQL (Data Query Language).

Ojo: TRUNCATE borra todas las filas como DELETE sin WHERE, pero se considera DDL: no dispara triggers de fila, es más rápido, no admite WHERE y en Oracle hace COMMIT implícito (no se puede deshacer con ROLLBACK). En Oracle y MySQL toda sentencia DDL confirma implícitamente la transacción; PostgreSQL y SQL Server admiten DDL transaccional.

2.2. Elementos del lenguaje

  • No distingue mayúsculas en palabras clave e identificadores sin comillas; sí en los literales de cadena (según la intercalación o collation).

  • Literales de cadena entre comillas simples ('Madrid'); identificadores delimitados entre comillas dobles ("Nombre con espacios").

  • Comentarios: -- línea y /* bloque */.

  • Las sentencias terminan en ;.

  • Esquema = conjunto de objetos (tablas, vistas, índices...) de un usuario o espacio de nombres; catálogo = conjunto de esquemas. Los metadatos se consultan en INFORMATION_SCHEMA (estándar) o en el diccionario del producto (USER_TABLES en Oracle).

3. DDL: tablas, restricciones, índices y vistas

Esquema de ejemplo usado en todo el tema:

CREATE TABLE departamento (
  cod_dpto  INTEGER      PRIMARY KEY,
  nombre    VARCHAR(50)  NOT NULL UNIQUE,
  ciudad    VARCHAR(40)
);

CREATE TABLE empleado (
  dni       CHAR(9)       PRIMARY KEY,
  nombre    VARCHAR(60)   NOT NULL,
  salario   NUMERIC(8,2)  DEFAULT 1200 CHECK (salario > 0),
  fecha_alta DATE         NOT NULL,
  cod_dpto  INTEGER,
  jefe      CHAR(9),
  CONSTRAINT fk_emp_dpto FOREIGN KEY (cod_dpto)
    REFERENCES departamento (cod_dpto)
    ON DELETE SET NULL ON UPDATE CASCADE,
  CONSTRAINT fk_emp_jefe FOREIGN KEY (jefe) REFERENCES empleado (dni)
);

3.1. Restricciones (constraints)

RestricciónEfectoNulos
NOT NULLObliga a dar valorNo admite
UNIQUEValores no repetidos (clave alternativa)Admite (el estándar no considera iguales dos nulos)
PRIMARY KEY= UNIQUE + NOT NULL; una por tablaNo admite
FOREIGN KEY ... REFERENCESIntegridad referencialAdmite (salvo NOT NULL)
CHECK (condición)Condición de dominio; se viola solo si la condición es FALSA (DESCONOCIDO la cumple)—
DEFAULT valorValor por defecto (no es restricción propiamente)—

  • De columna (junto a la columna) o de tabla (al final; obligatorio para claves compuestas).

  • Se pueden nombrar con CONSTRAINT nombre y declarar diferibles (DEFERRABLE INITIALLY DEFERRED: se comprueban al hacer COMMIT).

  • Aserción (CREATE ASSERTION): restricción sobre varias tablas; está en el estándar pero casi ningún SGBD la implementa (se usan triggers).

  • Dominio (CREATE DOMAIN): tipo con restricciones reutilizable (PostgreSQL lo soporta).

3.2. ALTER y DROP

ALTER TABLE empleado ADD email VARCHAR(100);
ALTER TABLE empleado DROP COLUMN email;
ALTER TABLE empleado ADD CONSTRAINT ck_alta CHECK (fecha_alta >= DATE '2000-01-01');
ALTER TABLE empleado DROP CONSTRAINT ck_alta;

DROP TABLE empleado CASCADE;   -- elimina también objetos dependientes (vistas, FK)
DROP TABLE empleado RESTRICT;  -- falla si hay dependencias

3.3. Índices

Estructura auxiliar que acelera las búsquedas a costa de espacio y de ralentizar INSERT/UPDATE/DELETE. No forman parte del estándar SQL (pertenecen al nivel físico), aunque todos los SGBD los admiten.

CREATE INDEX idx_emp_nombre ON empleado (nombre);
CREATE UNIQUE INDEX idx_dpto_nombre ON departamento (nombre);
DROP INDEX idx_emp_nombre;
TipoUso
Árbol B / B+El más habitual; igualdades y rangos, ordenación
HashSolo igualdades
BitmapColumnas con pocos valores distintos (sexo, provincia); data warehouse
Agrupado (clustered)Ordena físicamente la tabla; solo uno por tabla (SQL Server)
CompuestoVarias columnas; sirve para búsquedas por el prefijo izquierdo

Los SGBD crean automáticamente un índice para PRIMARY KEY y UNIQUE.

3.4. Vistas

Una vista es una tabla virtual definida por una consulta; no almacena datos (salvo las materializadas). Sirven para seguridad (ocultar columnas o filas), simplificar consultas e independencia lógica.

CREATE VIEW emp_madrid AS
  SELECT e.dni, e.nombre, e.salario
  FROM empleado e JOIN departamento d ON e.cod_dpto = d.cod_dpto
  WHERE d.ciudad = 'Madrid'
  WITH CHECK OPTION;

  • Actualizable si, en general, se basa en una sola tabla, sin DISTINCT, GROUP BY, agregados ni operaciones de conjuntos, e incluye las columnas obligatorias. Para vistas no actualizables: triggers INSTEAD OF.

  • WITH CHECK OPTION: impide insertar o modificar filas que luego no serían visibles a través de la vista.

  • Vista materializada (Oracle, PostgreSQL): guarda físicamente el resultado y se refresca periódicamente; no es estándar SQL.

3.5. Otros objetos

  • Secuencias (CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; NEXT VALUE FOR s) y columnas identidad (GENERATED ALWAYS AS IDENTITY), ambas desde SQL:2003.

  • Sinónimos (Oracle), esquemas (CREATE SCHEMA), tablas temporales (CREATE GLOBAL TEMPORARY TABLE).

4. DML: consultas y modificación de datos

4.1. Estructura de SELECT y orden lógico de evaluación

SELECT   [DISTINCT] columnas, expresiones, agregados   -- 5
FROM     tablas / JOIN                                 -- 1
WHERE    condición sobre filas                         -- 2
GROUP BY columnas de agrupación                        -- 3
HAVING   condición sobre grupos                        -- 4
ORDER BY columnas [ASC | DESC]                         -- 6
OFFSET n ROWS FETCH FIRST m ROWS ONLY;                 -- 7

Orden lógico: FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → OFFSET/FETCH. Consecuencias de test:

  • En WHERE no se pueden usar funciones de agregado (se usa HAVING).

  • En WHERE no se pueden usar los alias del SELECT; en ORDER BY sí.

  • Con GROUP BY, en el SELECT solo pueden aparecer columnas de agrupación y agregados.

  • Limitar filas: FETCH FIRST n ROWS ONLY (estándar, SQL:2008); LIMIT (MySQL, PostgreSQL); TOP (SQL Server); ROWNUM (Oracle antiguo).

4.3. Funciones de agregado y agrupación

FunciónNulos
COUNT(*)Cuenta todas las filas, incluidas las que tienen nulos
COUNT(col)Cuenta los valores no nulos de col
COUNT(DISTINCT col)Valores distintos no nulos

-- Departamentos con más de 5 empleados y su salario medio
SELECT cod_dpto, COUNT(*) AS num_emp, AVG(salario) AS media
FROM empleado
WHERE fecha_alta >= DATE '2020-01-01'
GROUP BY cod_dpto
HAVING COUNT(*) > 5
ORDER BY media DESC;

Extensiones: GROUP BY ROLLUP (a, b) (subtotales jerárquicos), CUBE (todas las combinaciones), GROUPING SETS.

4.4. Combinaciones (JOIN)

-- Empleados con el nombre de su departamento (incluidos los que no tienen)
SELECT e.nombre, d.nombre AS dpto
FROM empleado e LEFT JOIN departamento d ON e.cod_dpto = d.cod_dpto;

-- Empleado y nombre de su jefe (self join)
SELECT e.nombre, j.nombre AS jefe
FROM empleado e JOIN empleado j ON e.jefe = j.dni;

-- Departamentos sin empleados (anti-join)
SELECT d.nombre
FROM departamento d LEFT JOIN empleado e ON e.cod_dpto = d.cod_dpto
WHERE e.dni IS NULL;

Sintaxis antigua (SQL-89): FROM empleado e, departamento d WHERE e.cod_dpto = d.cod_dpto; (+) era la notación propia de Oracle para el outer join.

4.5. Subconsultas

TipoEjemplo
Escalar (un valor)WHERE salario > (SELECT AVG(salario) FROM empleado)
De lista con IN, ANY/SOME, ALLWHERE salario > ALL (SELECT salario FROM empleado WHERE cod_dpto = 10)
Correlacionada (usa columnas de la consulta externa; se evalúa por cada fila)ver abajo
En el FROM (tabla derivada)FROM (SELECT ...) t
CTE (WITH) y recursiva (WITH RECURSIVE, SQL:1999)Jerarquías (organigramas)
-- Empleados que ganan más que la media de SU departamento (correlacionada)
SELECT e.nombre, e.salario
FROM empleado e
WHERE e.salario > (SELECT AVG(x.salario)
                   FROM empleado x
                   WHERE x.cod_dpto = e.cod_dpto);

-- Departamentos con al menos un empleado
SELECT d.nombre FROM departamento d
WHERE EXISTS (SELECT 1 FROM empleado e WHERE e.cod_dpto = d.cod_dpto);

  • = ANY equivale a IN; <> ALL equivale a NOT IN.

  • > ALL (conjunto vacío) es verdadero; > ANY (conjunto vacío) es falso.

  • Trampa clásica: NOT IN (subconsulta) cuando la subconsulta devuelve algún NULL no devuelve ninguna fila (la comparación da DESCONOCIDO). NOT EXISTS no tiene ese problema.

4.7. Funciones de ventana (SQL:2003)

SELECT nombre, cod_dpto, salario,
       RANK() OVER (PARTITION BY cod_dpto ORDER BY salario DESC) AS puesto,
       SUM(salario) OVER (PARTITION BY cod_dpto) AS total_dpto
FROM empleado;

A diferencia de GROUP BY, no agrupan filas: cada fila conserva su detalle. Funciones: ROW_NUMBER, RANK (deja huecos tras empates), DENSE_RANK (sin huecos), LAG, LEAD, agregados con OVER.

Otras funciones frecuentes: CASE WHEN ... THEN ... ELSE ... END, COALESCE(a, b, ...) (primer valor no nulo), NULLIF(a, b), CAST(x AS tipo), UPPER, LOWER, TRIM, SUBSTRING, CHAR_LENGTH, || (concatenación estándar), CURRENT_DATE, EXTRACT(YEAR FROM fecha).

4.8. INSERT, UPDATE, DELETE y MERGE

INSERT INTO departamento (cod_dpto, nombre, ciudad) VALUES (10, 'Informática', 'Madrid');
INSERT INTO departamento VALUES (20, 'RR. HH.', 'Sevilla'), (30, 'Registro', NULL);
INSERT INTO historico (dni, salario) SELECT dni, salario FROM empleado;  -- desde consulta

UPDATE empleado SET salario = salario * 1.02 WHERE cod_dpto = 10;

DELETE FROM empleado WHERE fecha_alta < DATE '2000-01-01';
-- Sin WHERE, UPDATE y DELETE afectan a TODAS las filas

MERGE INTO empleado t                     -- "upsert" (SQL:2003)
USING nuevos s ON (t.dni = s.dni)
WHEN MATCHED THEN UPDATE SET salario = s.salario
WHEN NOT MATCHED THEN INSERT (dni, nombre, salario, fecha_alta)
                      VALUES (s.dni, s.nombre, s.salario, CURRENT_DATE);

5. DCL y TCL: seguridad, transacciones y concurrencia

5.1. Privilegios: GRANT y REVOKE

GRANT SELECT, INSERT ON empleado TO usuario1;
GRANT UPDATE (salario) ON empleado TO rrhh;            -- privilegio sobre columna
GRANT SELECT ON emp_madrid TO PUBLIC;                  -- a todos los usuarios
GRANT SELECT ON empleado TO usuario2 WITH GRANT OPTION; -- puede concederlo a otros

CREATE ROLE consulta;
GRANT SELECT ON departamento TO consulta;
GRANT consulta TO usuario3;

REVOKE INSERT ON empleado FROM usuario1;
REVOKE SELECT ON empleado FROM usuario2 CASCADE;       -- revoca también lo que concedió

  • Privilegios sobre objetos: SELECT, INSERT, UPDATE, DELETE, REFERENCES, USAGE, TRIGGER, EXECUTE (rutinas), o ALL PRIVILEGES.

  • Roles: agrupan privilegios para simplificar la administración.

  • WITH GRANT OPTION permite propagar el privilegio; WITH ADMIN OPTION (Oracle) es su equivalente para privilegios de sistema y roles.

  • Las vistas completan la seguridad limitando filas y columnas visibles.

5.2. Transacciones y propiedades ACID

Una transacción es una unidad lógica de trabajo: un conjunto de operaciones que se ejecutan todas o ninguna.

PropiedadSignificadoQuién la garantiza
AtomicidadTodo o nadaGestor de recuperación (registro de log, undo)
ConsistenciaLleva la BD de un estado válido a otro válidoRestricciones de integridad + programador
Aislamiento (Isolation)Las transacciones concurrentes no se interfierenControl de concurrencia (bloqueos, MVCC)
DurabilidadLo confirmado persiste aunque falle el sistemaGestor de recuperación (redo, log en disco)
START TRANSACTION;                 -- BEGIN en PostgreSQL/SQL Server; implícita en Oracle
UPDATE cuenta SET saldo = saldo - 100 WHERE id = 1;
SAVEPOINT tras_cargo;
UPDATE cuenta SET saldo = saldo + 100 WHERE id = 2;
-- ROLLBACK TO SAVEPOINT tras_cargo;  -- deshace solo hasta el punto de salvaguarda
COMMIT;                            -- confirma; ROLLBACK desharía todo

  • Autocommit: muchos clientes confirman cada sentencia automáticamente.

  • Estados de una transacción: activa → parcialmente confirmada → confirmada; o fallida → abortada.

5.3. Problemas de concurrencia y niveles de aislamiento

FenómenoDescripción
Lectura sucia (dirty read)Se lee un dato modificado por otra transacción aún no confirmada
Lectura no repetible (non-repeatable read)Releer la misma fila da otro valor porque otra transacción la modificó y confirmó
Fantasma (phantom)Repetir una consulta con condición devuelve filas nuevas insertadas por otra transacción
Actualización perdida (lost update)Dos transacciones actualizan el mismo dato y una sobrescribe a la otra

Niveles del estándar (SQL-92), de menor a mayor aislamiento:

NivelLectura suciaNo repetibleFantasma
READ UNCOMMITTEDPosiblePosiblePosible
READ COMMITTEDEvitaPosiblePosible
REPEATABLE READEvitaEvitaPosible
SERIALIZABLEEvitaEvitaEvita
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

  • El nivel por defecto en el estándar es SERIALIZABLE. En la práctica: Oracle, PostgreSQL y SQL Server usan por defecto READ COMMITTED; MySQL (InnoDB), REPEATABLE READ.

  • A más aislamiento, menos concurrencia y más bloqueos.

  • Mecanismos: bloqueos (compartidos/lectura S y exclusivos/escritura X; bloqueo en dos fases, 2PL, garantiza serializabilidad), marcas de tiempo y MVCC (control multiversión: los lectores no bloquean a los escritores; Oracle, PostgreSQL, InnoDB).

  • Interbloqueo (deadlock): dos transacciones esperan cada una un recurso que tiene la otra; el SGBD lo detecta y aborta una (la víctima).

  • Granularidad de bloqueo: BD, tabla, página, fila. SELECT ... FOR UPDATE bloquea las filas leídas.

6. Procedimientos almacenados

Un procedimiento almacenado es un programa con nombre, escrito en un lenguaje procedimental del SGBD, que se compila y guarda en la propia base de datos y se ejecuta en el servidor. El estándar es SQL/PSM (Persistent Stored Modules, parte 4 de ISO/IEC 9075, añadido en 1996).

DialectoSGBD
PL/SQLOracle
T-SQL (Transact-SQL)Microsoft SQL Server, Sybase
PL/pgSQLPostgreSQL (admite también otros lenguajes: PL/Python, PL/Perl)
SQL/PSM (muy cercano)MySQL, MariaDB, IBM Db2 (SQL PL)
Java (SQL/JRT, parte 13)Oracle, Db2

6.1. Ventajas e inconvenientes

VentajasInconvenientes
Menos tráfico de red (una llamada en vez de muchas sentencias)Dependencia del fabricante (dialectos no portables)
Rendimiento: código precompilado y plan reutilizableLógica de negocio repartida entre aplicación y BD
Seguridad: se concede EXECUTE sin dar acceso directo a las tablas; ayuda frente a inyección SQL si se usan parámetrosDepuración, pruebas y control de versiones más difíciles
Reutilización y reglas de negocio centralizadasCarga adicional en el servidor de BD

6.2. Procedimiento frente a función almacenada

ProcedimientoFunción
Valor de retornoNo (resultados mediante parámetros OUT)Sí, con RETURN
InvocaciónCALL (estándar), EXEC (T-SQL), bloque PL/SQLDentro de una expresión o de un SELECT

6.3. Ejemplo (sintaxis SQL/PSM, válida en MySQL)

DELIMITER //
CREATE PROCEDURE subir_salario(IN p_dpto INT, IN p_pct DECIMAL(5,2),
                               OUT p_filas INT)
BEGIN
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    ROLLBACK;
    SET p_filas = -1;
  END;

  START TRANSACTION;
  UPDATE empleado
     SET salario = salario * (1 + p_pct / 100)
   WHERE cod_dpto = p_dpto;
  SET p_filas = ROW_COUNT();
  COMMIT;
END //
DELIMITER ;

CALL subir_salario(10, 2.5, @n);
SELECT @n;

(DELIMITER es un comando del cliente mysql, no de SQL: permite usar ; dentro del cuerpo.)

6.4. Ejemplo en PL/SQL (Oracle)

CREATE OR REPLACE FUNCTION salario_medio(p_dpto IN NUMBER)
RETURN NUMBER IS
  v_media NUMBER;
BEGIN
  SELECT AVG(salario) INTO v_media FROM empleado WHERE cod_dpto = p_dpto;
  RETURN NVL(v_media, 0);
END;
/

SELECT nombre, salario_medio(cod_dpto) FROM departamento;

Estructura de un bloque PL/SQL: DECLARE (opcional) → BEGIN (obligatorio) → EXCEPTION (opcional) → END;. Los paquetes (PACKAGE = especificación + cuerpo) agrupan procedimientos, funciones y variables. Excepciones predefinidas frecuentes: NO_DATA_FOUND (un SELECT ... INTO sin filas) y TOO_MANY_ROWS (devuelve más de una).

6.5. Elementos procedimentales

  • Variables: DECLARE v INT DEFAULT 0; y asignación SET v = ... (PSM) o v := ... (PL/SQL); SELECT ... INTO v.

  • Control de flujo: IF ... THEN ... ELSEIF ... ELSE ... END IF, CASE, LOOP, WHILE ... DO ... END WHILE, REPEAT ... UNTIL ... END REPEAT, FOR, LEAVE / ITERATE (PSM), EXIT (PL/SQL).

  • Cursores: permiten recorrer fila a fila el resultado de una consulta. Ciclo: DECLARE → OPEN → FETCH (en bucle) → CLOSE.

  • Excepciones / manejadores: DECLARE CONTINUE | EXIT HANDLER FOR ... (PSM, MySQL), EXCEPTION WHEN ... THEN (PL/SQL), TRY ... CATCH (T-SQL). Se lanzan errores con SIGNAL (PSM) o RAISE_APPLICATION_ERROR (Oracle).

  • SQL dinámico: PREPARE / EXECUTE (PSM), EXECUTE IMMEDIATE (PL/SQL).

-- Cursor en SQL/PSM (MySQL), dentro de un BEGIN ... END
DECLARE fin INT DEFAULT 0;
DECLARE v_nombre VARCHAR(60);
DECLARE c CURSOR FOR SELECT nombre FROM empleado WHERE cod_dpto = 10;
DECLARE CONTINUE HANDLER FOR NOT FOUND SET fin = 1;
OPEN c;
bucle: LOOP
  FETCH c INTO v_nombre;
  IF fin = 1 THEN LEAVE bucle; END IF;
  -- procesar v_nombre
END LOOP;
CLOSE c;

Gestión: ALTER PROCEDURE, DROP PROCEDURE nombre, GRANT EXECUTE ON PROCEDURE nombre TO usuario.

7. Eventos y disparadores

Un disparador (trigger) es un procedimiento almacenado que el SGBD ejecuta automáticamente cuando ocurre un evento sobre una tabla o vista; no se invoca explícitamente ni recibe parámetros. Entraron en el estándar en SQL:1999. Siguen el modelo ECA: Evento → Condición → Acción (base de las BD activas).

7.1. Clasificación

CriterioOpciones
EventoINSERT, UPDATE (opcionalmente UPDATE OF columna), DELETE. Algunos SGBD: TRUNCATE (PostgreSQL), DDL (CREATE, ALTER, DROP) y de sistema (LOGON, STARTUP en Oracle)
MomentoBEFORE (antes de la operación: validar o modificar los valores nuevos), AFTER (después: auditoría, propagar cambios), INSTEAD OF (en lugar de la operación; sobre vistas, SQL:2008)
GranularidadFOR EACH ROW (de fila: una vez por cada fila afectada) / FOR EACH STATEMENT (de sentencia: una vez por sentencia, aunque afecte a 0 filas). En el estándar, por defecto de sentencia
CondiciónWHEN (condición) opcional

Valores antiguo y nuevo (solo en triggers de fila):

EventoOLDNEW
INSERTNo existeFila insertada
UPDATEFila antes del cambioFila después del cambio
DELETEFila borradaNo existe

En el estándar se nombran con REFERENCING OLD ROW AS ... NEW ROW AS ...; en Oracle se escriben :OLD y :NEW; en MySQL y PostgreSQL, OLD y NEW. SQL Server usa las tablas virtuales inserted y deleted (solo triggers de sentencia AFTER e INSTEAD OF).

7.2. Ejemplos

-- BEFORE de fila (MySQL): normalizar y validar antes de guardar
CREATE TRIGGER trg_emp_bi
BEFORE INSERT ON empleado
FOR EACH ROW
BEGIN
  SET NEW.nombre = UPPER(NEW.nombre);
  IF NEW.salario < 1000 THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Salario inferior al mínimo';
  END IF;
END;
-- AFTER de fila (Oracle): auditoría de cambios de salario
CREATE OR REPLACE TRIGGER trg_aud_salario
AFTER UPDATE OF salario ON empleado
FOR EACH ROW
WHEN (NEW.salario <> OLD.salario)
BEGIN
  INSERT INTO auditoria (dni, sal_ant, sal_nuevo, fecha, usuario)
  VALUES (:OLD.dni, :OLD.salario, :NEW.salario, SYSDATE, USER);
END;
/
-- PostgreSQL: el trigger llama a una función que devuelve TRIGGER
CREATE FUNCTION f_fecha_mod() RETURNS trigger AS $$
BEGIN
  NEW.ult_modif := now();
  RETURN NEW;            -- en BEFORE, devolver NULL cancelaría la operación en esa fila
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_fecha_mod BEFORE UPDATE ON empleado
FOR EACH ROW EXECUTE FUNCTION f_fecha_mod();

Detalle de Oracle: en la cláusula WHEN se escribe NEW/OLD sin dos puntos; en el cuerpo, con ellos (:NEW).

7.3. Usos y precauciones

Usos típicos: auditoría (quién cambió qué y cuándo), reglas de negocio complejas que no expresan CHECK ni FK, integridad entre tablas (sustituto de las aserciones), mantener columnas derivadas o tablas resumen (desnormalización), replicación, hacer actualizables las vistas (INSTEAD OF), generar claves.

Precauciones:

  • Cascada de triggers: un trigger puede disparar otros; los SGBD limitan la profundidad.

  • Tabla mutante (Oracle, error ORA-04091): un trigger de fila no puede consultar ni modificar la misma tabla que lo disparó. Solución: trigger de sentencia o compound trigger.

  • Un trigger forma parte de la transacción de la sentencia que lo dispara: si falla, se deshace la sentencia completa. Normalmente no puede hacer COMMIT ni ROLLBACK.

  • Lógica «oculta» y coste en rendimiento: documentarlos y no abusar.

  • Orden de ejecución habitual: triggers BEFORE de sentencia → para cada fila (BEFORE de fila → operación y comprobación de restricciones → AFTER de fila) → AFTER de sentencia.

Gestión: DROP TRIGGER nombre; desactivar: ALTER TRIGGER nombre DISABLE (Oracle), ALTER TABLE t DISABLE TRIGGER nombre (PostgreSQL, SQL Server).

7.4. Eventos programados

Además de los eventos que activan triggers, algunos SGBD permiten eventos temporales: tareas que se ejecutan según un calendario, no por una operación sobre los datos (equivalen a un cron dentro de la BD).

SGBDMecanismo
MySQL / MariaDBCREATE EVENT con el Event Scheduler (variable event_scheduler activada)

SQL ServerTrabajos del SQL Server Agent

-- MySQL: purga diaria de registros antiguos
CREATE EVENT ev_purga_log
ON SCHEDULE EVERY 1 DAY
STARTS '2026-01-01 03:00:00'
DO
  DELETE FROM log_accesos WHERE fecha < NOW() - INTERVAL 90 DAY;

ON SCHEDULE AT CURRENT_TIMESTAMP + INTERVAL 1 HOUR

Esquema de repaso

  • Lenguajes de interrogación: formales (álgebra procedimental; cálculo declarativo), comerciales (SQL, QUEL, QBE), otros (XQuery, SPARQL, Cypher, GQL ISO/IEC 39075:2024).

  • SQL: declarativo; origen SEQUEL (Chamberlin y Boyce, IBM, System R). Primer estándar ANSI 1986, ISO 1987; norma actual ISO/IEC 9075.

  • Versiones clave: SQL-92 (JOIN explícitos, aislamiento) · SQL:1999 (triggers, recursividad, OO) · SQL:2003 (ventana, MERGE, identidad, XML) · SQL:2008 (TRUNCATE, INSTEAD OF) · SQL:2011 (temporal) · SQL:2016 (JSON) · SQL:2023 (vigente: SQL/PGQ parte 16, tipo JSON).

  • DDL CREATE/ALTER/DROP/TRUNCATE · DML SELECT/INSERT/UPDATE/DELETE/MERGE · DCL GRANT/REVOKE · TCL COMMIT/ROLLBACK/SAVEPOINT.

  • TRUNCATE es DDL: sin WHERE, sin triggers de fila; en Oracle no se puede deshacer.

  • CHAR fijo / VARCHAR variable; NUMERIC(p,s): p dígitos totales, s decimales.

  • PRIMARY KEY = UNIQUE + NOT NULL, una por tabla; UNIQUE admite nulos; CHECK solo falla si la condición es FALSA.

  • Índices no son estándar SQL (nivel físico): B-tree (rangos), hash (igualdad), bitmap (pocos valores).

  • Vistas: tablas virtuales; WITH CHECK OPTION; no actualizables con DISTINCT, GROUP BY, agregados → INSTEAD OF.

  • Orden lógico: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. Agregados en HAVING, no en WHERE.

  • COUNT(*) cuenta todas las filas; COUNT(col) y SUM/AVG/MIN/MAX ignoran nulos.

  • BETWEEN incluye extremos; LIKE: % cualquier cadena, _ un carácter; IS NULL, nunca = NULL.

  • JOIN: INNER, LEFT/RIGHT/FULL OUTER, CROSS (producto), NATURAL (columnas del mismo nombre), self join.

  • Subconsultas: escalares, IN/ANY/ALL, correlacionadas, EXISTS; NOT IN con NULL devuelve 0 filas.

  • UNION elimina duplicados, UNION ALL no; EXCEPT = MINUS (Oracle).

  • ACID: atomicidad, consistencia, aislamiento, durabilidad. Fenómenos: lectura sucia, no repetible, fantasma.

  • Niveles: READ UNCOMMITTED < READ COMMITTED (evita sucia) < REPEATABLE READ (evita no repetible) < SERIALIZABLE (evita fantasma; defecto del estándar).

  • Procedimientos almacenados (SQL/PSM, 1996): se ejecutan en el servidor, se invocan con CALL, parámetros IN/OUT/INOUT; funciones devuelven valor con RETURN. Cursores: DECLARE → OPEN → FETCH → CLOSE.

  • Triggers (SQL:1999, modelo ECA): BEFORE/AFTER/INSTEAD OF × FOR EACH ROW/STATEMENT; OLD (UPDATE, DELETE) y NEW (INSERT, UPDATE); tabla mutante ORA-04091.

  • Eventos programados: CREATE EVENT ... ON SCHEDULE (MySQL), DBMS_SCHEDULER (Oracle), SQL Server Agent.
