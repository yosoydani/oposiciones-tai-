1. Aplicaciones web: arquitectura y protocolo HTTP

Una aplicación web se ejecuta en un servidor y se usa desde un navegador (cliente ligero) mediante HTTP/HTTPS. No requiere instalación en el puesto y se actualiza en un único punto.

1.1 Arquitectura

CapaFunciónEjemplos
Presentación (cliente)Interfaz: estructura, estilo, comportamientoHTML, CSS, JavaScript, React, Angular, Vue
Lógica de negocio (servidor)Procesa peticiones, reglas, seguridadJava (Jakarta EE, Spring), PHP, Node.js, Python, C# (.NET)
DatosPersistenciaOracle, PostgreSQL, MySQL, MongoDB

  • Servidor web: sirve recursos estáticos y reenvía peticiones (Apache HTTP Server, Nginx, IIS).

  • Servidor de aplicaciones / contenedor: ejecuta la lógica (Tomcat = contenedor de servlets; WildFly/JBoss, WebLogic = Jakarta EE completo).

  • Modelos de renderizado: SSR (el servidor genera el HTML, clásico con PHP/JSP), CSR (el navegador construye la página con JavaScript, típico de las SPA), SSG (páginas generadas en compilación) e híbridos (Next.js, Nuxt).

  • Patrón MVC (Modelo-Vista-Controlador): separa datos, presentación y control. Variantes: MVP, MVVM (Angular, Vue).

1.2 URL

https://www.ejemplo.es:443/ruta/recurso.html?id=5&lang=es#seccion

ParteValor
Esquemahttps
Hostwww.ejemplo.es
Puerto443 (por defecto en HTTPS; 80 en HTTP)
Ruta/ruta/recurso.html
Consulta (query)?id=5&lang=es

URI es el identificador genérico; URL indica la localización; URN da un nombre persistente (p. ej. urn:isbn:...).

1.3 HTTP

Protocolo de aplicación, petición-respuesta y sin estado (stateless).

VersiónRasgos clave
HTTP/1.0 (1996)Una conexión TCP por petición
HTTP/1.1 (1997, RFC 2068)Conexiones persistentes (keep-alive), cabecera Host obligatoria, chunked
HTTP/2 (2015)Binario, multiplexación de flujos en una conexión, compresión de cabeceras HPACK
HTTP/3 (2022, RFC 9114)Sobre QUIC (UDP), cabeceras QPACK, TLS 1.3 integrado

La semántica común a todas las versiones está en el RFC 9110 (2022). HTTPS = HTTP sobre TLS.

Métodos

MétodoUsoSeguroIdempotente
GETObtener recursoSíSí
HEADComo GET sin cuerpoSíSí
POSTCrear / enviar datosNoNo
PUTReemplazar recursoNoSí
PATCHModificación parcialNoNo (en general)

Códigos de estado

ClaseSignificadoEjemplos
1xxInformativo100 Continue, 101 Switching Protocols
2xxÉxito200 OK, 201 Created, 204 No Content

Cabeceras habituales: Content-Type (tipo MIME, p. ej. application/json), Accept, Authorization, Cache-Control, Set-Cookie / Cookie, Location (redirecciones), ETag.

1.4 Estado: cookies y sesiones

Como HTTP no guarda estado, se usan:

  • Cookie: dato que el servidor envía con Set-Cookie y el navegador devuelve en cada petición al mismo dominio. Atributos: Expires/Max-Age (persistente; sin ellos es de sesión), Domain, Path, Secure (solo HTTPS), HttpOnly (inaccesible desde JavaScript: mitiga robo por XSS), SameSite (Strict, Lax, None: mitiga CSRF).

  • Sesión: estado guardado en el servidor, asociado a un identificador (p. ej. JSESSIONID, PHPSESSID) que viaja normalmente en una cookie.

  • Tokens: autenticación sin estado, p. ej. JWT (JSON Web Token: cabecera.carga.firma, en Base64URL), enviado en Authorization: Bearer.

  • Almacenamiento web en el navegador: localStorage (persistente), sessionStorage (por pestaña), IndexedDB (base de datos de objetos). No viajan solos al servidor.

1.5 Política del mismo origen y CORS

  • Origen = esquema + host + puerto. La política del mismo origen (SOP) impide que un script lea respuestas de otro origen.

  • CORS (Cross-Origin Resource Sharing) permite que el servidor autorice otros orígenes con cabeceras: Access-Control-Allow-Origin, -Allow-Methods, -Allow-Headers, -Allow-Credentials.

  • Peticiones no simples (p. ej. PUT, o JSON con cabeceras propias) provocan una petición previa (preflight) con OPTIONS.

  • Con credenciales (cookies) no se admite Access-Control-Allow-Origin: *.

1.6 Servicios y formatos de intercambio

  • REST: recursos identificados por URI, verbos HTTP, sin estado; normalmente JSON.

  • SOAP: mensajes XML, descritos con WSDL.

  • GraphQL: el cliente pide exactamente los campos que necesita, con un único punto de acceso.

  • WebSocket (ws://, wss://): canal bidireccional y persistente, iniciado con un upgrade HTTP (101).

  • Server-Sent Events: flujo unidireccional servidor → cliente.

2. Lenguajes de marcado: HTML, XML y sus derivaciones

Un lenguaje de marcado anota un texto con etiquetas que indican estructura o significado; no es un lenguaje de programación (no tiene control de flujo). Todos derivan de SGML (ISO 8879, 1986).

2.1 Evolución de HTML

VersiónAñoNota
HTML 2.01995Primer estándar (IETF, RFC 1866)
HTML 4.011999W3C; variantes Strict, Transitional, Frameset
XHTML 1.02000HTML reformulado como XML (sintaxis estricta)
HTML52014Recomendación W3C; semántica, multimedia, API
HTML Living StandardcontinuoMantenido por WHATWG; desde el acuerdo W3C-WHATWG de 2019 es la única especificación de HTML

Hoy no hay «HTML6»: el estándar es vivo (se actualiza de forma continua).

2.2 Estructura mínima de un documento

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Título de la página</title>
  <link rel="stylesheet" href="estilos.css">
</head>
<body>
  <h1>Encabezado principal</h1>
  <script src="app.js" defer></script>
</body>
</html>

  • <!DOCTYPE html> activa el modo estándar (no es una etiqueta, es una declaración).

  • lang en <html> declara el idioma (clave para lectores de pantalla).

  • defer: el script se descarga en paralelo y se ejecuta tras analizar el HTML, en orden; async: se ejecuta en cuanto llega, sin orden garantizado.

2.3 HTML semántico

ElementoSignificado

<nav>Bloque de navegación principal

<article>Contenido autónomo y redistribuible (noticia, entrada)
<section>Agrupación temática, normalmente con encabezado
<aside>Contenido complementario (barra lateral)
<figure> + <figcaption>Ilustración con su pie
<time datetime="2026-11-11">Fecha u hora legible por máquina

<div>, <span>Sin significado (bloque / línea)

Otros elementos de HTML5: <audio>, <video> (con <track> para subtítulos), <canvas> (dibujo por script, mapa de bits), <svg> integrado, <dialog>, <details>/<summary>, <picture> y srcset (imágenes adaptables), <template>. Elementos eliminados: <font>, <center>, <frame>/<frameset>, <marquee>.

2.4 Formularios

  • <form action="/alta" method="post">; method admite GET (datos en la URL) o POST (en el cuerpo).

  • Tipos de <input> de HTML5: email, url, tel, number, range, date, time, color, search, file, password, checkbox, radio, hidden.

  • Validación nativa: required, pattern, min, max, maxlength, step. La validación en cliente no sustituye a la de servidor.

  • <label for="id"> asocia la etiqueta al control (accesibilidad). Otros: <select>, <textarea>, <fieldset>/<legend>, <datalist>, <output>.

  • Codificación del envío: application/x-www-form-urlencoded (por defecto) o multipart/form-data (obligatoria para subir ficheros).

2.5 XML

XML (eXtensible Markup Language, W3C, 1998) sirve para describir e intercambiar datos; las etiquetas las define el usuario.

  • Bien formado: un único elemento raíz, toda etiqueta cerrada, anidamiento correcto, distingue mayúsculas, valores de atributos entre comillas.

  • Válido: bien formado y conforme a un esquema (DTD o XSD).

  • Espacios de nombres (xmlns) evitan colisiones de nombres.

  • Secciones <![CDATA[ ... ]]>: texto que no se analiza.

TecnologíaFunción
DTDGramática del documento; sintaxis no XML, sin tipos de datos
XSD (XML Schema)Esquema escrito en XML, con tipos de datos
XPathLenguaje para seleccionar nodos (/libro/titulo, //autor[@id='1'])
XSLTTransforma XML en otro XML, HTML o texto
XQueryConsulta de colecciones XML
DOM / SAX / StAXAnalizadores: DOM carga el árbol en memoria; SAX es secuencial por eventos (menos memoria)

3. CSS y diseño adaptable

CSS (Cascading Style Sheets, W3C) define la presentación; HTML define la estructura. Desde CSS3 la especificación se divide en módulos independientes (Selectors, Flexbox, Grid...), sin un «CSS4» único.

3.1 Formas de aplicar estilos

FormaEjemploPrioridad
En línea<p style="color:red">La más alta (salvo !important)
Interna<style> en el <head>Según especificidad y orden
Externa<link rel="stylesheet" href="a.css">Según especificidad y orden; se cachea y reutiliza

3.2 Selectores y especificidad

SelectorEjemploEspecificidad
Universal*0-0-0
Tipo / pseudoelementop, ::before0-0-1
Clase, atributo, pseudoclase.aviso, [type="text"], :hover0-1-0
Identificador#menu1-0-0

Combinadores: descendiente (nav a), hijo (ul > li), hermano adyacente (h1 + p), hermano general (h1 ~ p).

Cascada: decide el valor final por (1) origen e importancia (!important), (2) especificidad, (3) orden de aparición (gana la última). Algunas propiedades se heredan (color, font-family) y otras no (margin, border).

3.3 Modelo de caja

Cada elemento es una caja: contenido → padding (relleno) → border (borde) → margin (margen).

  • box-sizing: content-box (por defecto): width mide solo el contenido.

  • box-sizing: border-box: width incluye relleno y borde.

  • display: block, inline, inline-block, none (no ocupa espacio; visibility: hidden sí lo ocupa), flex, grid.

  • position: static (defecto), relative, absolute (respecto al ancestro posicionado), fixed (respecto a la ventana), sticky.

3.4 Maquetación

TécnicaDimensionesUso
FlexboxUna (fila o columna)Barras, alinear elementos (justify-content, align-items)
GridDos (filas y columnas)Rejillas de página (grid-template-columns: 1fr 2fr)

3.5 Unidades

  • Absolutas: px, cm, pt.

  • Relativas: %, em (tamaño de fuente del padre), rem (del elemento raíz), vw/vh (1 % del ancho/alto de la ventana).

  • Para accesibilidad se prefieren unidades relativas (permiten ampliar el texto).

3.6 Diseño adaptable (responsive)

  • Media queries: @media (max-width: 600px) { ... }; también prefers-color-scheme, prefers-reduced-motion, print.

  • Metaetiqueta viewport (width=device-width) para móviles.

  • Rejillas fluidas e imágenes flexibles (max-width: 100%).

  • Mobile first: se diseña primero para la pantalla pequeña y se añaden estilos con min-width.

  • Diseño adaptable (un solo sitio que se ajusta) frente a adaptive (varias plantillas fijas por dispositivo).

3.7 Herramientas

  • Preprocesadores: Sass/SCSS, Less (variables, anidamiento, mixins) que se compilan a CSS. CSS ya tiene variables nativas: --color: #333; color: var(--color);.

  • Frameworks CSS: Bootstrap (rejilla de 12 columnas), Tailwind CSS (clases utilitarias), Foundation.

  • Postprocesadores (PostCSS, Autoprefixer) añaden prefijos de fabricante (-webkit-, -moz-).

4. JavaScript, DOM, AJAX y lenguajes de script

4.1 Lenguajes de script

Un lenguaje de script es normalmente interpretado (o compilado al vuelo, JIT), de tipado dinámico y pensado para automatizar o controlar otro programa o entorno.

ÁmbitoLenguajes
Cliente webJavaScript; TypeScript (se transpila a JS); históricos: VBScript, ActionScript (Flash)
Servidor webPHP, JavaScript (Node.js), Python, Ruby, Perl
Sistema / administraciónBash y shells Unix, PowerShell, ficheros .bat/.cmd, Python
IncrustadosLua (videojuegos), VBA (ofimática)

4.2 JavaScript y ECMAScript

  • Creado por Brendan Eich en Netscape (1995). Nada que ver con Java salvo el nombre.

  • Estandarizado como ECMAScript por Ecma International: norma ECMA-262 (TC39); también ISO/IEC 16262.

  • Desde 2015 hay una edición al año, nombrada por el año.

EdiciónNovedades de test
ES3 (1999)Expresiones regulares, try/catch
ES5 (2009)Modo estricto ("use strict"), JSON nativo, forEach/map
ES6 = ES2015let/const, funciones flecha =>, class, Promesas, módulos import/export, plantillas `Hola ${n}`, desestructuración
ES2017async/await
ES2020Encadenamiento opcional ?., fusión nula ??, BigInt
ES2026 (17.ª edición, aprobada el 30-6-2026)Math.sumPrecise, Iterator.concat, Array.fromAsync, Error.isError, Base64/hex en Uint8Array, JSON.rawJSON

Rasgos del lenguaje

  • Tipado dinámico y débil; multiparadigma (imperativo, funcional, orientado a objetos basado en prototipos).

  • Tipos primitivos: string, number, bigint, boolean, undefined, symbol, null; el resto son objetos. Curiosidad de test: typeof null devuelve "object".

  • var (ámbito de función, hoisting) frente a let/const (ámbito de bloque).

  • == compara con conversión de tipos; === compara valor y tipo ("5" == 5 es true; "5" === 5 es false).

  • Monohilo con bucle de eventos (event loop): la asincronía se maneja con callbacks, promesas y async/await. Los Web Workers permiten ejecutar en otro hilo.

4.3 DOM

El DOM (Document Object Model, hoy estándar vivo del WHATWG) representa la página como un árbol de nodos manipulable por scripts.

const btn = document.querySelector('#enviar');      // primer elemento que casa
const items = document.querySelectorAll('.item');   // NodeList
btn.addEventListener('click', (e) => {
  e.preventDefault();                              // evita el envío del formulario
  const p = document.createElement('p');
  p.textContent = 'Enviado';                       // texto plano: seguro frente a XSS
  document.body.appendChild(p);
});

  • Selección: getElementById, getElementsByClassName, querySelector(All).

  • textContent inserta texto; innerHTML interpreta HTML (riesgo de XSS con datos del usuario).

  • Eventos: click, submit, input, change, keydown, load, DOMContentLoaded. Fases: captura → objetivo → burbujeo; stopPropagation() detiene la propagación. Delegación de eventos: un manejador en el padre atiende a los hijos.

  • BOM (Browser Object Model): window, navigator, location, history, screen.

4.4 AJAX y fetch

AJAX (Asynchronous JavaScript And XML, término de 2005) = pedir datos al servidor sin recargar la página y actualizar parte del DOM. Pese al nombre, hoy suele usar JSON.

APIRasgos
XMLHttpRequestClásica, basada en eventos/callbacks
fetch()Moderna, devuelve una Promesa; no rechaza ante 404/500 (hay que comprobar response.ok)
LibreríasjQuery $.ajax, Axios
async function cargar() {
  const r = await fetch('/api/expedientes/7', { headers: { Accept: 'application/json' } });
  if (!r.ok) throw new Error('HTTP ' + r.status);
  const datos = await r.json();
  console.log(datos.titulo);
}

  • JSON.stringify(obj) convierte objeto → texto; JSON.parse(texto) texto → objeto.

  • Las peticiones a otro origen están sujetas a CORS (apartado 1.5).

4.5 Ecosistema y herramientas

  • TypeScript (Microsoft): superconjunto de JS con tipado estático; se transpila a JavaScript.

  • WebAssembly (Wasm): formato binario que el navegador ejecuta a velocidad casi nativa (compilado desde C, C++, Rust...).

  • Gestores de paquetes: npm (fichero package.json), Yarn, pnpm.

  • Empaquetadores y compilación: Webpack, Vite, esbuild; Babel transpila JS moderno a versiones antiguas.

  • Calidad: ESLint (análisis estático), Prettier (formato), Jest/Vitest (pruebas unitarias).

5. Desarrollo front-end, multiplataforma y multidispositivo

El front-end es la parte que se ejecuta en el navegador y ve el usuario; el back-end, la que se ejecuta en el servidor. Un perfil full-stack cubre ambas.

5.1 Frameworks y librerías de JavaScript

HerramientaOrigenRasgos de test

AngularGoogle, 2016Framework completo en TypeScript; inyección de dependencias; enlace de datos bidireccional; CLI. No confundir con AngularJS (2010, JavaScript, descontinuado)
Vue.jsEvan You, 2014Framework progresivo (adopción gradual); componentes de un solo fichero .vue; reactividad

Conceptos

  • SPA (Single Page Application): una sola página HTML; las vistas cambian con JavaScript y el enrutado es del cliente. Pros: fluidez. Contras: carga inicial, SEO y accesibilidad requieren cuidado.

  • DOM virtual: copia ligera del DOM en memoria; se calculan las diferencias y solo se aplican los cambios.

  • Componentes: piezas reutilizables con su estado y vista. Web Components es el estándar nativo (Custom Elements, Shadow DOM, plantillas HTML).

  • Gestión del estado: Redux, Pinia (Vue), NgRx (Angular).

5.2 Aplicaciones web progresivas (PWA)

Una PWA es una web que se comporta como una app: instalable, funciona sin conexión y puede recibir notificaciones push. Requisitos:

  1. Servirse por HTTPS.

  2. Un manifiesto de aplicación web (manifest.json: nombre, iconos, colores, modo de pantalla).

  3. Un service worker: script en segundo plano que intercepta peticiones y gestiona la caché.

5.3 Multidispositivo

Una misma web debe funcionar en ordenador, tableta, móvil o TV:

  • Diseño adaptable (responsive) con media queries, rejillas fluidas y mobile first (apartado 3.6).

  • Mejora progresiva (progressive enhancement): base de HTML que funciona en todos, y se añaden CSS y JS. Su opuesto es la degradación elegante (graceful degradation).

  • Interacción táctil: eventos touch y pointer events; objetivos táctiles grandes.

  • Rendimiento: imágenes adaptables (srcset), carga diferida (loading="lazy"), compresión, CDN.

5.5 Rendimiento y calidad

  • Core Web Vitals (Google): LCP (carga del contenido mayor), INP (respuesta a la interacción), CLS (estabilidad visual).

  • Herramientas: Lighthouse (rendimiento, accesibilidad, buenas prácticas, SEO), herramientas de desarrollador del navegador.

  • Minificación, agrupación (bundling), división de código (code splitting) y caché HTTP.

6. Desarrollo web en servidor

El servidor recibe la petición HTTP, aplica la lógica de negocio y la seguridad, accede a datos y devuelve HTML (renderizado en servidor) o datos (JSON/XML para una API).

6.1 Evolución

  1. Páginas estáticas: ficheros HTML servidos tal cual.

  2. CGI (Common Gateway Interface): el servidor lanza un proceso por petición (Perl, C). Poco eficiente; mejorado por FastCGI (procesos persistentes).

  3. Páginas con código incrustado: PHP, ASP (clásico, VBScript), JSP.

  4. Frameworks MVC y servicios REST; hoy, microservicios, contenedores y serverless.

6.2 Lenguajes y plataformas

TecnologíaRasgosFrameworks

Pilas típicas: LAMP (Linux, Apache, MySQL, PHP), MEAN (MongoDB, Express, Angular, Node.js), MERN (con React).

6.3 Ejemplos mínimos

<?php
$nombre = htmlspecialchars($_GET['nombre'] ?? 'mundo'); // escapa la salida
echo "<p>Hola, $nombre</p>";
// Node.js con Express
const express = require('express');
const app = express();
app.get('/api/hola', (req, res) => res.json({ mensaje: 'Hola' }));
app.listen(3000);

Superglobales de PHP: $_GET, $_POST, $_REQUEST, $_SESSION (requiere session_start()), $_COOKIE, $_SERVER, $_FILES.

6.4 Elementos comunes del back-end

  • Enrutado: asocia URL y método HTTP a un controlador.

  • Plantillas (templates): generan HTML con datos (Thymeleaf, Twig, Blade, Jinja2, Razor). Deben escapar la salida por defecto.

  • ORM (Object-Relational Mapping): objetos ↔ tablas (Hibernate/JPA en Java, Entity Framework en .NET, Doctrine en PHP, ORM de Django). Usan consultas parametrizadas.

  • API REST documentadas con OpenAPI (Swagger).

  • Autenticación y autorización: sesiones, JWT, OAuth 2.0 (delegación de autorización), OpenID Connect (identidad sobre OAuth 2.0), SAML (federación, p. ej. Cl@ve en la AGE).

  • Middleware: funciones que procesan la petición en cadena (registro, autenticación, compresión).

6.5 Despliegue

  • Servidores web: Apache HTTP Server (módulos, .htaccess), Nginx (asíncrono, muy usado como proxy inverso y balanceador), IIS (Microsoft).

  • Contenedores Docker y orquestación con Kubernetes.

  • Serverless / FaaS: funciones ejecutadas bajo demanda (AWS Lambda, Azure Functions).

7.3 Componentes y proceso de renderizado

Componentes: interfaz de usuario, motor del navegador, motor de renderizado, red, intérprete de JavaScript, backend gráfico y almacenamiento de datos.

Ruta de renderizado:

  1. Analiza el HTML y construye el DOM.

  2. Analiza el CSS y construye el CSSOM.

  3. Combina ambos en el árbol de renderizado (solo nodos visibles).

  4. Layout (o reflow): calcula posición y tamaño.

  5. Paint: dibuja píxeles.

  6. Composite: compone capas.

Un <script> sin defer/async bloquea el análisis del HTML.

7.6 Seguridad del navegador

  • Política del mismo origen y CORS (apartado 1.5).

  • CSP (Content Security Policy): cabecera que limita de dónde se cargan scripts y otros recursos (mitiga XSS).

  • HSTS (Strict-Transport-Security): obliga a usar HTTPS.

  • Avisos de certificado (cadena de confianza de la PKI), sandbox por proceso y aislamiento de sitios.

  • Cadena User-Agent: identifica navegador y sistema; no es fiable para detectar capacidades (mejor la detección de características).

Esquema de repaso

  • Aplicación web = cliente (navegador) + servidor web/aplicaciones + datos, comunicados por HTTP/HTTPS.

  • HTTP: aplicación, petición-respuesta, sin estado; HTTP/2 multiplexa; HTTP/3 va sobre QUIC (UDP), RFC 9114; semántica en RFC 9110.

  • Métodos idempotentes: GET, HEAD, PUT, DELETE, OPTIONS; POST no. 401 = sin autenticar, 403 = sin permiso, 404 = no existe, 503 = no disponible.

  • Estado: cookies (Secure, HttpOnly, SameSite), sesión en servidor, tokens JWT, almacenamiento web.

  • Origen = esquema + host + puerto; CORS lo concede el servidor; preflight con OPTIONS.

  • HTML hoy = HTML Living Standard del WHATWG (acuerdo con el W3C de 2019).

  • Semántica: header, nav, main, article, section, aside, footer; div/span sin significado.

  • XML: bien formado (sintaxis) frente a válido (DTD/XSD). XSD tiene tipos; XPath selecciona; XSLT transforma; DOM árbol en memoria, SAX por eventos.

  • Derivados de XML: XHTML, SVG, MathML, RSS/Atom, SOAP/WSDL, Facturae.

  • CSS: cascada = importancia, especificidad (id > clase > tipo), orden. Modelo de caja: contenido, padding, border, margin.

  • Flexbox = una dimensión; Grid = dos. rem relativo a la raíz, em al padre.

  • Responsive: media queries, viewport, mobile first.

  • JavaScript (Eich, Netscape, 1995) = ECMAScript, ECMA-262; ES2015 = ES6; vigente ES2026 (17.ª edición).

  • === compara valor y tipo; let/const ámbito de bloque; monohilo con event loop.

  • DOM: árbol de nodos; innerHTML interpreta HTML (riesgo XSS), textContent no.

  • AJAX = petición asíncrona sin recargar; fetch devuelve Promesa y no rechaza por 404.

  • React = librería (Meta, JSX, DOM virtual); Angular = framework TypeScript (Google); Vue = progresivo.

  • PWA = HTTPS + manifiesto + service worker. Flutter usa Dart; React Native, JS; Electron, escritorio.

  • Servidor: PHP, Java (Servlets/JSP, Spring), .NET (ASP.NET Core), Node.js (V8, asíncrono), Python (Django, Flask). LAMP / MEAN.

  • Motores: Blink (Chrome, Edge), Gecko (Firefox), WebKit (Safari); JS: V8, SpiderMonkey, JavaScriptCore.
