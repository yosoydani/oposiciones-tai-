1. Lenguajes de programación

Un lenguaje de programación es un lenguaje formal, con sintaxis (reglas de forma) y semántica (significado) definidas, que permite escribir instrucciones ejecutables por un ordenador. Un programa = algoritmos + estructuras de datos (N. Wirth).

  • Fases del compilador: análisis léxico (tokens) → sintáctico (árbol, gramática) → semántico (tipos) → código intermedio → optimización → generación de código. Después, el enlazador (linker) une módulos y bibliotecas y el cargador (loader) lo sube a memoria.

  • Soluciones híbridas: Java compila a bytecode que ejecuta la JVM; .NET compila a CIL que ejecuta el CLR. Ambos usan JIT (Just-In-Time): compilan a código nativo en tiempo de ejecución.

2. Representación de tipos de datos

Un tipo de dato define un conjunto de valores, su representación en memoria y las operaciones permitidas. Clasificación:

  • Simples / primitivos / escalares: entero, real, carácter, lógico, enumerado.

  • Compuestos / estructurados: vectores (arrays), registros, cadenas, conjuntos, ficheros.

  • Punteros / referencias: contienen una dirección de memoria.

  • Abstractos (TAD): definidos por sus operaciones, no por su implementación (pila, cola, lista).

2.1. Enteros

RepresentaciónRango con n bitsCaracterísticas
Sin signo (binario natural)0 a 2ⁿ − 18 bits: 0 a 255
Signo-magnitud−(2ⁿ⁻¹ − 1) a +(2ⁿ⁻¹ − 1)Doble cero (+0 y −0)
Complemento a 1−(2ⁿ⁻¹ − 1) a +(2ⁿ⁻¹ − 1)Negativo = invertir bits; doble cero
Complemento a 2−2ⁿ⁻¹ a 2ⁿ⁻¹ − 1Un solo cero; la que usan los ordenadores. 8 bits: −128 a 127
Exceso a 2ⁿ⁻¹ (sesgo)−2ⁿ⁻¹ a 2ⁿ⁻¹ − 1Se usa en el exponente de IEEE 754

Complemento a 2 de un número: invertir bits y sumar 1. Ejemplo con 8 bits: +5 = 00000101 → invertir 11111010 → +1 → −5 = 11111011.

Desbordamiento (overflow): el resultado no cabe en el rango. En Java Integer.MAX_VALUE + 1 da Integer.MIN_VALUE (−2.147.483.648) sin error.

2.2. Reales: coma flotante IEEE 754

Número = (−1)^signo × 1,mantisa × 2^(exponente − sesgo). La mantisa está normalizada con un bit implícito (el 1 inicial no se guarda).

Valores especiales: ±0 (exponente y mantisa a 0), ±infinito (exponente todo a 1, mantisa 0), NaN (exponente todo a 1, mantisa ≠ 0), subnormales (exponente 0, mantisa ≠ 0).

Ojo: 0,1 no tiene representación exacta en binario: en casi todos los lenguajes 0.1 + 0.2 == 0.3 es falso. Para importes se usan tipos decimales (BigDecimal en Java, DECIMAL en SQL, decimal en C#).

Otras representaciones: coma fija; BCD (Binary Coded Decimal, 4 bits por dígito decimal; usado en COBOL, COMP-3 = decimal empaquetado).

2.4. Lógico, enumerados y punteros

  • Lógico / booleano: verdadero o falso. En C clásico no existe: 0 es falso y cualquier otro valor verdadero (_Bool desde C99).

  • Enumerado: conjunto finito de constantes con nombre (enum Dia {LUNES, MARTES}).

  • Subrango (Pascal): 1..12.

  • Puntero: dirección de memoria. Operadores en C: &x (dirección de x) y *p (contenido apuntado). El valor nulo es NULL/null/None.

2.6. Conversiones de tipo

  • Implícita / coerción / promoción: automática hacia un tipo más amplio (int → double). Conversión de ensanchamiento (widening), segura.

  • Explícita / casting: la pide el programador: (int) 3.9 da 3 (trunca). Conversión de estrechamiento (narrowing): puede perder información.

  • Boxing / unboxing (Java, C#): conversión automática entre primitivo y objeto envoltorio (int ↔ Integer).

2.7. Variables y constantes

  • Variable: nombre + tipo + valor + dirección + ámbito + tiempo de vida.

  • Constante: valor que no cambia (final en Java, const en C/C#/JavaScript).

  • Literal: valor escrito en el código (42, 3.14, 'a', "hola", 0x1F hexadecimal, 0b101 binario).

  • Identificadores: suelen empezar por letra o _; sensibles a mayúsculas en C, Java, Python; no en Pascal, COBOL, SQL (palabras clave).

3. Operadores y expresiones

Una expresión combina operandos (variables, constantes, llamadas) y operadores para producir un valor. Por número de operandos: unarios (-x, !a, ++i), binarios (a + b) y ternarios (c ? x : y).

Equivalencias en otros lenguajes: Python usa and, or, not, // (división entera), ** (potencia) y no tiene ++; Pascal usa div, mod, := para asignar; SQL usa = para comparar y <> para distinto; JavaScript distingue == (con conversión) y === (igualdad estricta, sin conversión).

3.2. Precedencia y asociatividad

De mayor a menor prioridad (C/Java, simplificado):

  1. Postfijos: (), [], ., x++, x--

  2. Unarios: ++x, --x, +x, -x, !, ~, cast

  3. Multiplicativos: * / %

  4. Aditivos: + -

  5. Desplazamiento: << >> >>>

  6. Relacionales: < > <= >=, instanceof

  7. Igualdad: == !=

  8. AND de bits & → XOR ^ → OR de bits |

  9. AND lógico &&

  10. OR lógico ||

  11. Ternario ?:

  12. Asignación = += -= ... (asociatividad de derecha a izquierda)

  • La mayoría de operadores binarios son asociativos por la izquierda: 10 - 4 - 3 = (10 − 4) − 3 = 3.

  • La asignación y los unarios son asociativos por la derecha: a = b = 5 asigna 5 a b y luego a a.

  • Los paréntesis alteran la precedencia.

Ejemplos de test:

int a = 2 + 3 * 4;        // 14 (no 20)
int b = 17 % 5;           // 2
int c = 7 / 2;            // 3 (entera)
double d = 7 / 2;         // 3.0 (se divide en entero y luego se convierte)
double e = 7 / 2.0;       // 3.5
int i = 5; int j = i++;   // j = 5, i = 6
int k = 5; int m = ++k;   // m = 6, k = 6
boolean f = (3 > 2) || (1 / 0 == 0); // true: cortocircuito, no se divide por 0

Signo del resto: en C y Java el resto toma el signo del dividendo (-7 % 3 = −1; -7 / 2 = −3). En Python la división entera redondea hacia −infinito (-7 // 2 = −4) y el resto toma el signo del divisor (-7 % 3 = 2).

Leyes de De Morgan: NOT (A AND B) = (NOT A) OR (NOT B); NOT (A OR B) = (NOT A) AND (NOT B).

Operaciones de bits: 12 & 10 = 1100 & 1010 = 1000 = 8; 12 | 10 = 1110 = 14; 12 ^ 10 = 0110 = 6; 5 << 2 = 20.

3.4. Efectos laterales y sobrecarga

  • Efecto lateral: una expresión que, además de devolver un valor, modifica el estado (i++, una llamada que cambia una global). En C, expresiones como i = i++ + 1 tienen comportamiento indefinido.

  • Sobrecarga de operadores: el mismo símbolo con distinto significado según el tipo. + suma números y concatena cadenas en Java. C++, C# y Python permiten al programador sobrecargar operadores; Java no (salvo el + de String, predefinido).

4. Instrucciones condicionales

La programación estructurada se basa en el teorema de Böhm-Jacopini (1966): todo programa con un único punto de entrada y de salida puede escribirse con solo tres estructuras de control: secuencia, selección (condicional) e iteración (bucle). Dijkstra popularizó la idea en 1968 con su carta «Go To Statement Considered Harmful».

4.1. Tipos de selección

EstructuraPseudocódigoEjecuta
Simplesi C entonces A fin_siA solo si C es verdadera
Doblesi C entonces A si_no B fin_siA o B, nunca ambas
Múltiple / anidadasi C1 ... si_no si C2 ... si_no ...El primer bloque cuya condición se cumple
Selección por casossegún V hacer caso 1: ... caso 2: ... otro: ...El caso que coincide con el valor de V
if (nota >= 9) {
    calif = "Sobresaliente";
} else if (nota >= 7) {
    calif = "Notable";
} else if (nota >= 5) {
    calif = "Aprobado";
} else {
    calif = "Suspenso";
}

4.2. switch / case

switch (dia) {
    case 1:  printf("Lunes");  break;
    case 2:  printf("Martes"); break;
    case 6:
    case 7:  printf("Fin de semana"); break;
    default: printf("Otro día");
}

  • En C, C++ y Java (forma clásica), sin break la ejecución continúa en el caso siguiente (fall-through).

  • C# prohíbe el fall-through implícito entre casos con instrucciones.

  • Java admite en switch tipos enteros (byte, short, char, int y sus envoltorios), enum y String (desde Java 7); las expresiones switch con -> son estándar desde Java 14.

  • Python no tuvo switch hasta la sentencia match (Python 3.10, structural pattern matching).

  • En Pascal: case ... of; en COBOL: EVALUATE; en SQL: expresión CASE WHEN ... THEN ... ELSE ... END.

4.3. Operador ternario y otras formas

String tipo = (edad >= 18) ? "adulto" : "menor";

Python: tipo = "adulto" if edad >= 18 else "menor".

4.4. Errores típicos de test

  • Else colgante (dangling else): en if (a) if (b) x; else y; el else se asocia al if más cercano (el de b).

  • En C, if (x = 5) asigna (y siempre es verdadero), no compara.

  • Comparar reales con == es poco fiable (redondeo de coma flotante).

  • En Java, == entre objetos String compara referencias; para contenido se usa equals().

5. Bucles y recursividad

5.1. Estructuras iterativas

BucleComprobaciónNº mínimo de ejecucionesUso típico
Mientras (while)Al principio (pretest)0Número de iteraciones desconocido
Repetir / hacer-mientras (do...while, repeat...until)Al final (postest)1Menús, validar entradas

Ojo: repeat ... until C (Pascal) repite hasta que C sea verdadera; do ... while (C) (C/Java) repite mientras C sea verdadera. Condiciones opuestas.

// while: suma de 1 a n
int suma = 0, i = 1;
while (i <= n) { suma += i; i++; }

// do-while: se ejecuta al menos una vez
do { opcion = leerOpcion(); } while (opcion != 0);

// for clásico
for (int k = 0; k < v.length; k++) { total += v[k]; }

// for-each
for (int x : v) { total += x; }

Control del bucle:

  • break: sale del bucle (o del switch) más interno.

  • continue: salta a la siguiente iteración.

  • Etiquetas (break etiqueta; en Java) para salir de bucles anidados.

Conceptos: contador (variable que se incrementa en cantidad fija), acumulador (va sumando o multiplicando valores), centinela (valor especial que marca el final de la entrada), interruptor / bandera (flag, variable lógica que indica si ha ocurrido algo), bucle infinito (la condición nunca se hace falsa).

Número de iteraciones de for (i = a; i < b; i += p) con p > 0: ⌈(b − a) / p⌉. Ejemplo: for (i = 0; i < 10; i += 3) itera con i = 0, 3, 6, 9 → 4 veces.

5.2. Recursividad

Un subprograma es recursivo cuando se llama a sí mismo, directa o indirectamente. Requisitos:

  1. Caso base (condición de parada): se resuelve sin recursión.

  2. Caso recursivo: se reduce el problema hacia el caso base.

Sin caso base (o si no se alcanza) se produce un desbordamiento de pila (StackOverflowError en Java). Cada llamada crea un registro de activación en la pila (parámetros, variables locales, dirección de retorno).

int factorial(int n) {
    if (n <= 1) return 1;            // caso base
    return n * factorial(n - 1);     // caso recursivo
}

int fib(int n) {                     // recursividad múltiple
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
TipoDescripciónEjemplo
DirectaEl subprograma se llama a sí mismo.factorial
Indirecta / mutuaA llama a B y B llama a A.esPar(n) ↔ esImpar(n)
Lineal / simpleUna sola llamada recursiva por ejecución.Factorial
Múltiple / en árbolVarias llamadas recursivas.Fibonacci, recorridos de árboles
De cola (tail)La llamada recursiva es la última operación; el compilador puede convertirla en bucle (sin crecer la pila).fact(n, acc) = fact(n−1, n·acc)
AnidadaUn argumento es otra llamada recursiva.Función de Ackermann

Recursividad frente a iteración:

  • Toda función recursiva puede escribirse de forma iterativa (usando, si hace falta, una pila explícita), y viceversa.

  • La recursiva suele ser más clara (árboles, divide y vencerás: quicksort, mergesort, torres de Hanoi) pero consume más memoria (pila) y tiempo por las llamadas.

  • fib recursivo ingenuo tiene coste exponencial; con memoización (programación dinámica) o iterativo es lineal.

  • Torres de Hanoi con n discos: 2ⁿ − 1 movimientos.

Traza: factorial(4) = 4 · factorial(3) = 4 · 3 · factorial(2) = 4 · 3 · 2 · factorial(1) = 4 · 3 · 2 · 1 = 24; profundidad máxima de pila: 4 llamadas.

6. Procedimientos, funciones y parámetros

Un subprograma (subrutina, módulo) es un bloque de código con nombre que realiza una tarea y puede invocarse desde varios puntos. Ventajas: modularidad, reutilización, abstracción (diseño descendente, divide y vencerás), legibilidad y mantenimiento más sencillo.

6.1. Procedimiento frente a función

ProcedimientoFunción
Devuelve valorNo (puede devolver resultados mediante parámetros de salida)Sí, uno (con return)
LlamadaComo instrucción independienteDentro de una expresión
Ejemploimprimir(informe);x = raiz(16) + 1;
En C/JavaFunción/método voidFunción/método con tipo de retorno
En Pascalprocedurefunction

  • Función pura: el resultado depende solo de los argumentos y no tiene efectos laterales (base del paradigma funcional; transparencia referencial).

  • Firma / signatura / prototipo: nombre + número, orden y tipo de parámetros (en Java el tipo de retorno no forma parte de la firma).

  • Sobrecarga: varios subprogramas con el mismo nombre y distinta lista de parámetros (Java, C++, C#; no en C ni en Python clásico).

6.2. Parámetros formales y reales

  • Parámetros formales: los declarados en la definición del subprograma (int suma(int a, int b)).

  • Parámetros reales / argumentos / actuales: los valores o variables que se pasan en la llamada (suma(x, 3)).

  • La correspondencia suele ser posicional; algunos lenguajes admiten por nombre (f(b=2, a=1) en Python), valores por defecto y número variable de argumentos (int... v en Java, *args en Python).

6.3. Modos de paso de parámetros

ModoQué se pasa¿Cambios visibles fuera?Dirección

Por referencia (dirección)La dirección de la variableSíEntrada/salida

Por lenguaje:

  • C: solo por valor; el paso por referencia se simula pasando un puntero (void inc(int *p) { (*p)++; } y llamada inc(&x)).

  • C++: por valor y por referencia (void inc(int &x)).

  • Pascal: por valor y por referencia con var.

  • Ada: modos in, out, in out.

  • C#: por valor por defecto; ref y out para referencia.

  • Java: siempre por valor. Con objetos se copia el valor de la referencia: el método puede modificar el estado del objeto, pero no hacer que la variable del llamante apunte a otro objeto.

  • Python: paso por asignación (call by sharing): se pasan referencias a objetos; los cambios en objetos mutables (listas) se ven fuera, los de inmutables (int, str) no.

  • SQL/PL: parámetros IN, OUT, INOUT (IN OUT en PL/SQL).

Ejemplo de test:

void f(int a, int *b) {
    a = a + 10;      // cambia la copia local
    *b = *b + 10;    // cambia la variable original
}

int x = 1, y = 1;
f(x, &y);
// Resultado: x = 1, y = 11

6.5. Mecanismo de llamada

  1. Se evalúan los argumentos y se pasan según el modo.

  2. Se apila el registro de activación (stack frame): parámetros, variables locales, dirección de retorno.

  3. Se ejecuta el cuerpo.

  4. Se devuelve el resultado (si es función), se desapila el registro y se vuelve a la instrucción siguiente a la llamada.

Métricas de calidad modular: alta cohesión (cada módulo hace una sola cosa) y bajo acoplamiento (poca dependencia entre módulos).

7. Vectores y registros

7.1. Vectores (arrays)

Un vector (array, arreglo, tabla) es una estructura estática (en su forma clásica), homogénea (todos los elementos del mismo tipo) y de acceso directo por índice, cuyos elementos ocupan posiciones contiguas de memoria.

CaracterísticaDetalle
HomogéneoMismo tipo en todos los elementos
Acceso directoCoste O(1) para leer o escribir v[i]
TamañoFijo al crearlo (C, Java); dinámico en ArrayList, listas de Python, vector de C++
Índice inicial0 en C, C++, Java, C#, Python, JavaScript; 1 en Fortran, COBOL, MATLAB, Lua; definible en Pascal (array[1..10])
DimensionesUnidimensional (vector), bidimensional (matriz), multidimensional
int[] v = new int[5];          // 5 enteros inicializados a 0; índices 0..4
int[] w = {3, 8, 1};           // w.length == 3
int[][] m = new int[3][4];     // 3 filas, 4 columnas
v[5] = 1;                      // ArrayIndexOutOfBoundsException

En C no se comprueban los límites: escribir fuera del vector es comportamiento indefinido (origen de los desbordamientos de búfer).

Cálculo de direcciones (base 0, cada elemento ocupa t bytes):

  • Vector: dir(v[i]) = base + i · t.

  • Matriz de F filas y C columnas, por filas (row-major): dir(m[i][j]) = base + (i · C + j) · t.

  • Por columnas (column-major): dir(m[i][j]) = base + (j · F + i) · t.

  • Por filas: C, C++, Pascal. Por columnas: Fortran, MATLAB, R. En Java una matriz es un vector de vectores (las filas pueden tener distinta longitud: jagged arrays).

Ejemplo: int m[3][4] en C, base 1000, int de 4 bytes: dir(m[2][1]) = 1000 + (2 · 4 + 1) · 4 = 1036.

7.3. Registros

Un registro (struct en C, record en Pascal) es una estructura heterogénea: agrupa campos de distinto tipo bajo un nombre, accesibles por nombre de campo (no por índice).

struct Empleado {
    char dni[10];
    char nombre[50];
    double salario;
};

struct Empleado e;
e.salario = 2100.50;            // acceso con punto
struct Empleado *p = &e;
p->salario += 100;              // acceso mediante puntero con ->

struct Empleado plantilla[100]; // vector de registros

  • Registro variante (Pascal) / union (C): varios campos comparten la misma zona de memoria; solo uno es válido a la vez.

  • Equivalentes modernos: clases con solo atributos; record en Java (estándar desde Java 16), data classes en Kotlin y Python (@dataclass), struct en C# (tipo valor).

  • Ficheros: secuencias de registros almacenados en memoria secundaria (organización secuencial, directa o indexada).

7.4. Estructuras dinámicas (relación con el tema)

Con punteros y registros se construyen estructuras de tamaño variable en el montículo (heap): listas enlazadas, pilas (LIFO), colas (FIFO), árboles y grafos. La memoria se reserva con malloc/free en C, new/delete en C++ y new en Java (liberada por el recolector de basura, garbage collector).

8. Estructura de un programa

8.1. Partes generales

  1. Cabecera / identificación: nombre del programa, paquete o módulo.

  2. Importaciones / inclusiones: bibliotecas externas (#include, import, using).

  3. Declaraciones: constantes, tipos, variables globales.

  4. Subprogramas: procedimientos y funciones (o métodos de clases).

  5. Programa principal / punto de entrada: donde empieza la ejecución (main).

  6. Comentarios y documentación a lo largo de todo el código.

En cuanto a la lógica, todo programa sigue el esquema entrada → proceso → salida.

8.2. Ejemplos por lenguaje

/* C */
#include <stdio.h>            /* directiva del preprocesador */
#define IVA 0.21              /* constante */

double con_iva(double base);  /* prototipo */

int main(void) {              /* punto de entrada */
    double precio = 100.0;
    printf("%.2f\n", con_iva(precio));
    return 0;                 /* 0 = terminación correcta */
}

double con_iva(double base) { return base * (1 + IVA); }
// Java
package es.gob.ejemplo;
import java.util.List;

public class Principal {
    private static final double IVA = 0.21;

    public static void main(String[] args) {   // punto de entrada
        System.out.println(conIva(100.0));
    }

    static double conIva(double base) { return base * (1 + IVA); }
}

  • En Java todo el código está dentro de clases; un fichero .java contiene como máximo una clase pública de primer nivel, que debe llamarse igual que el fichero.

  • En Python no hace falta main: el código se ejecuta de arriba abajo; el modismo if __name__ == "__main__": distingue ejecución directa de importación. Los bloques se delimitan por sangrado, no por llaves.

  • En Pascal: program Nombre; → const → type → var → procedimientos y funciones → begin ... end. (punto final).

  • En COBOL: cuatro divisiones en orden: IDENTIFICATION, ENVIRONMENT, DATA y PROCEDURE.

8.4. Buenas prácticas

  • Programación estructurada y modular; diseño descendente (top-down, refinamiento sucesivo, Wirth).

  • Nombres significativos y convenciones: camelCase (Java), snake_case (Python, PEP 8), PascalCase para clases, MAYÚSCULAS para constantes.

  • Comentarios: de línea (//, #, -- en SQL) y de bloque (/* ... */); de documentación (Javadoc /** ... */, docstrings en Python).

  • Tratamiento de errores: excepciones (try / catch / finally en Java y C#; try / except / finally en Python).

  • Evitar goto, variables globales y «números mágicos» (usar constantes con nombre).

Esquema de repaso

  • Niveles: máquina → ensamblador → alto nivel → 4GL (SQL). Paradigmas: imperativo, estructurado, OO, funcional (Lisp, Haskell), lógico (Prolog).

  • Compilador traduce todo antes de ejecutar; intérprete línea a línea; Java/.NET: bytecode/CIL + máquina virtual + JIT.

  • Fases del compilador: léxico → sintáctico → semántico → intermedio → optimización → código. Sintaxis en BNF.

  • Tipado estático/dinámico (cuándo) y fuerte/débil (conversiones implícitas). Python: dinámico y fuerte.

  • Complemento a 2 con n bits: −2ⁿ⁻¹ a 2ⁿ⁻¹ − 1 (8 bits: −128 a 127); un solo cero.

  • IEEE 754: simple 32 bits (1 + 8 + 23, sesgo 127); doble 64 bits (1 + 11 + 52, sesgo 1023).

  • ASCII 7 bits; UTF-8 1-4 bytes, compatible con ASCII. Java: byte 8, short 16, int 32, long 64, float 32, double 64 y char 16 bits (UTF-16).

  • División entera: 7 / 2 = 3; 7 % 3 = 1; en Java/C -7 % 3 = −1; en Python -7 % 3 = 2.

  • i++ devuelve el valor antiguo; ++i el nuevo. && y || evalúan en cortocircuito.

  • Precedencia: unarios > * / % > + - > relacionales > igualdad > && > || > ternario > asignación (derecha a izquierda).

  • Böhm-Jacopini (1966): secuencia, selección, iteración. Dijkstra (1968) contra goto.

  • switch sin break → fall-through. else colgante → se asocia al if más cercano.

  • while 0..n veces (pretest); do-while 1..n (postest); repeat-until repite hasta que la condición sea verdadera.

  • Recursividad: caso base + caso recursivo; usa la pila; tipos directa/indirecta, lineal/múltiple, de cola, anidada (Ackermann). Hanoi: 2ⁿ − 1 movimientos.

  • Procedimiento no devuelve valor (se llama como instrucción); función devuelve uno (dentro de expresiones).

  • Parámetros formales (definición) y reales (llamada). Paso por valor (copia) / por referencia (dirección) / resultado / valor-resultado / nombre (ALGOL 60).

  • C solo por valor (referencia simulada con punteros); Java siempre por valor (copia de la referencia en objetos); Python call by sharing.

  • Vector: homogéneo, contiguo, acceso O(1) por índice (base 0 en C/Java/Python). Matrices: por filas (C) / por columnas (Fortran). dir = base + (i·C + j)·t.

  • Registro: heterogéneo, acceso por nombre de campo (. y -> en C); union comparte memoria; record de Java desde 16.

  • Estructura: cabecera, importaciones, declaraciones, subprogramas, principal (main); COBOL: IDENTIFICATION, ENVIRONMENT, DATA, PROCEDURE. Memoria: código, datos estáticos, pila (locales), montículo (dinámica).
